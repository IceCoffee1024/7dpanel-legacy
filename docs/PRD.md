# 7DPanel 产品需求文档

## 产品概述

7DPanel 面向《七日杀》服务器服主，提供随服务端运行的自托管 Mod DLL 和网页管理入口。产品将高频控制台操作、日常运维、玩家管理、自动备份和公告自动化集中到一个低门槛界面，帮助非专业服主减少持续在线值守，提升服务器生态的稳定性和可管理性。

首版目标是证明：服主可以脱离 Telnet 黑框，在服务器出现问题前获得自动化保障，出现问题后通过面板完成管理和恢复。

## 问题与目标

### 问题

对通常只管理一台服务器、技术水平一般的服主来说，当前主要依赖七日杀服务端控制台命令完成运维。操作分散、学习成本高，备份和玩家处置容易依赖人工值守；外挂、异常行为和管理低效会进一步破坏服务器生态。

### 产品目标

- 将服主从 7×24 小时人工救火式运维中解放出来。
- 让服主通过网页完成服务器状态查看和高频玩家管理。
- 通过计划备份与可验证的恢复流程降低数据丢失风险。
- 通过公告和基础自动化减少重复操作，建立可持续的服务器运营基础。

## 目标用户与价值

### 主要用户

- **公共社区服主**：需要自动化运营、任务、备份、玩家管理和通知。
- **小型好友服主**：需要低门槛配置、礼包、传送、商店和便利功能。
- **PvP/竞技服主**：需要审计搜索、案件证据、管理员追踪和异常提醒。

首版假设用户通常只管理 1 台服务器，并通过服务端自带控制台命令进行运维。

### 产品价值

服主可以在浏览器中看见服务器和玩家状态，执行常用管理动作，自动完成备份，并通过公告和定时触发器处理重复工作。产品替代的是依赖记忆、黑框命令和人工盯守的运维方式，而不是要求服主学习另一套复杂的专业系统。

## 范围与非目标

### 首版范围

- 服主自行部署随 7DTD 服务端运行的 Mod DLL，并通过网页面板管理该服务器。
- 单服务器接入、状态查看、玩家管理、网页控制台/日志、备份恢复、公告和有限的基础自动化。
- `Owner` 专用的实时聊天、历史聊天、聊天设置和彩色聊天管理。
- 管理员操作审计和失败状态反馈。

### 非目标

- 首版不承诺多服统一管理。
- 首版不提供玩家账号登录，不实现积分经济、网页/游戏内商店、礼包商城或玩家转账体系；未来若扩展玩家门户，玩家身份不得复用首版只读管理角色 `Viewer`。
- 首版不实现复杂的外挂检测、跨服黑名单、区域保护或自动封禁策略。
- 首版不实现 Discord 双向聊天、Discord 远程控制或通用可编程脚本平台。
- PRD 不规定具体前端组件、数据库结构、API、部署编排或技术选型。

## 产品能力

### CAP-01: 服务器接入与状态仪表盘

- **用户结果：** 服主能完成一台服务器接入，并在仪表盘首屏判断服务器是否在线、是否可管理。
- **Priority:** P0
- **Requirements:**
  - 用户部署 7DPanel Mod DLL 后，面板自动识别并验证当前所在的 7DTD 服务端，无需另行配置 Telnet 连接。
  - 面板显示连接状态、服务器运行状态、在线玩家数量和最近一次状态更新时间。
  - 认证后的综合快照必须把面板、游戏和主机信息与各自真实的采样时间及可用状态分开表达；游戏状态、主机状态和数据新鲜度不得相互推导或合并为单一“在线”结论。
  - 已授权的综合快照中某一分区暂时不可用或无权读取时，面板继续显示其他可用分区并明确标为部分可用；不得以零值、缺失字段或其他分区的数据冒充该分区成功。
  - 认证后的实时连接建立后先提供当前服务器欢迎快照，使客户端可以确认连接目标、产品版本和当前可管理状态，再接收后续命名事件。
  - 连接失败、服务端离线或状态过期时，面板明确显示原因或可执行的下一步。
- **验收标准：**
  - Given Mod DLL 已运行且引导 `Owner` 已同步，When 用户登录面板，Then 面板显示当前服务器已连接和最新状态。
  - Given 服务端不可达，When 用户打开仪表盘，Then 页面显示不可用状态，且不会把过期状态标记为正常。
  - Given 已认证用户取得综合快照，When 游戏、主机或采样信息分别变化或不可用，Then 面板分别显示它们的状态与时间，而不把其中一项代替另一项。
  - Given 综合快照的一项已授权分区不可用，When 其他分区仍有有效数据，Then 页面显示部分可用及受影响原因，且保留其他分区的真实数据与时间。
  - Given 用户建立有效的认证实时连接，When 连接开始传输，Then 客户端先收到当前服务器欢迎快照，且快照不会被误报为后续游戏事件。

### CAP-02: 实时玩家管理与网页控制台

- **用户结果：** 服主能在网页中完成高频玩家处置和日志排查，无需直接操作 Telnet 黑框。
- **Priority:** P0
- **Requirements:**
  - 面板显示在线玩家的名称、实体标识、原生与可选跨平台身份，以及设备、网络地址、延迟、兼容版本、可选 Discord 关联、权限等级、位置、存活与生命状态、等级、分数、击杀、死亡、累计游戏时长、步行距离、制作数量和当前/最长存活时长；缺失的可选值必须明确显示为未知，不得伪造默认事实。
  - 累计游戏时长、当前存活时长和最长存活时长以分钟表达，步行距离以米表达；界面可以为可读性格式化这些值，但不得改变单位含义或伪造精度。
  - 在线列表是由客户端最近一次有效玩家数据上传形成的最终一致视图，同一列表中的玩家可以来自不同上传时刻，新连接在首次有效上传前可以暂不出现。
  - 每个已显示玩家的身份、连接、位置、状态和统计字段必须来自该玩家同一次有效观察，并携带该次观察成功进入投影的 UTC 时间；服务端不定义统一的数据过期阈值或列表级新鲜度，接口调用者可以按自身场景解释数据年龄并提示用户。
  - 用户打开列表或详情不会改变玩家观察时间；一次新观察失败时继续返回上一条有效观察及其原时间，不把失败时刻伪装成新数据。
  - 面板为 `Owner` 提供历史玩家的只读查询。历史按有效的跨平台身份 `crossplatformIdentity.combinedId` 归档；缺少该身份的在线观察不进入历史，不得以名称、网络地址、实体标识或原生平台身份猜测合并。
  - 每次有效 `SavePlayerData` 观察都可以尽力写入本机历史，即使字段未变化；写入必须经有界后台队列进行，不能等待 SQLite 或阻塞游戏主线程。队列满、持久化失败和关服排空超时必须形成可读的历史缺口，不得伪造连续记录。
  - 历史快照保留在线观察的全部字段，并额外记录可用的玩家组、游戏持久记录中的最近登录时间、游戏阶段、距下级经验、技能点和床铺位置。最近登录时间不等于观察时间，也不表示玩家在两个时间点之间持续在线；缺失字段必须保留为未知。
  - 历史列表显示玩家摘要与数据质量，详情按时间倒序分页展示只读快照；计划内降采样与非计划历史缺口必须区分。历史页不提供踢出、禁言、封禁、传送、删除、导出或身份合并。
  - 在线玩家投影可读时统一返回成功响应。该端点不返回 `online_player_projection_stale`、`online_player_query_busy`、`game_thread_timeout` 或 `online_player_snapshot_unavailable`；游戏尚未就绪、认证和授权失败语义保持不变，其他端点仍可拥有自己的 `game_thread_timeout`。
  - 具备踢出、禁言、封禁、传送等首版确认的高频管理动作；危险动作必须明确确认。
  - “控制台与日志”页面只允许 `Owner` 和 `Admin` 访问；`Viewer` 与未认证用户不能读取最近控制台日志、实时控制台日志或动态命令目录。
  - 页面进入时显示服务端内存中保留的最近原始控制台日志，并在同一视图继续追加实时日志；日志不承诺跨服务端进程重启保留，超出服务端保留窗口或实时连接无法补齐时必须明确标记缺口。
  - 日志区域只显示服务端提供的原始日志文本，不按关键字、级别或时间隐藏记录，不自动识别或链接玩家、IP、坐标、命令和审计对象，也不插入浏览器生成的命令行、命令输出或系统消息。
  - 用户位于日志底部时页面自动跟随最新记录；用户滚动离开底部后不得抢回滚动位置，并持续显示尚未查看的新日志数量和“回到最新”入口。
  - 用户可以清空当前页面会话中已经显示的日志；该操作不得删除服务端内存窗口、审计数据或重置实时游标，后续新日志继续到达。重新进入页面时仍按正常规则读取服务端最近日志。
  - 网页控制台允许 `Owner` 和 `Admin` 执行当前 7DTD 进程已经注册的全部控制台命令，包括服务端自带命令和其他 Mod 注册的命令；产品不维护命令白名单，也不保证第三方命令的业务语义、幂等性或成功判定。
  - 页面从当前 7DTD 进程动态读取命令名称、别名、说明、帮助和有效权限等级；缺少可选元数据的命令仍可执行。命令目录不可用时，用户仍可自由输入命令，不得把建议目录变成执行白名单。
  - 命令输入对第一个命令词提供名称和别名前缀建议，支持键盘选择与补全；页面会话内可以恢复最近成功提交的命令，但命令历史不得写入浏览器持久存储。
  - 所有控制台命令均由用户按 Enter 直接提交，不按命令名称增加浏览器确认。提交成功后页面不展示请求返回的独立输出，而是等待原生控制台日志作为普通实时日志出现；提交被拒绝、超时、权限不足或结果未知时只提供短暂反馈，不向原始日志流插入面板消息。
  - 网页控制台请求按接收顺序进入有界等待队列并在游戏主线程串行执行；队列容量不足、游戏尚未就绪、排队期间取消和执行结果未知时必须返回可区分状态，不得无界投递或伪造成功。
  - 所有正常经过 7DTD 控制台执行边界的命令都尽力记录完整命令原文、来源、时间、返回输出和可判断的结果；审计暂时不可用时命令继续执行，但产品必须留下可见告警且不得宣称审计完整。绕过控制台直接调用游戏 API 的第三方 Mod 行为不属于该审计保证。
  - 首版动态命令入口暂不承诺应用级请求长度、参数长度、输出行数、单行长度或总输出大小限制，也不承诺抗滥用和资源隔离；底层运行环境限制或资源耗尽仍可能导致请求失败或服务端性能下降。
  - 同一个认证实时连接可以传递日志、服务器生命周期和连接状态等命名事件；同一 API major 内事件名称和含义保持不变，断线重连后能够按可用游标补取，无法补齐时必须明确标记缺口。
  - 结构化控制台命令状态暂不通过实时连接传输；网页发起的命令通过原请求获得结果，原生控制台执行日志仍可作为普通日志事件出现。
  - 管理动作记录执行者、目标、时间、动作结果和失败原因。
- **验收标准：**
  - Given 玩家刚进入游戏但尚未完成首次有效玩家数据上传，When 管理员查看在线列表，Then 该玩家可以暂不出现，且其他已有有效数据的玩家仍可显示。
  - Given 多名玩家的最后有效数据来自不同时间，When 管理员刷新在线列表，Then 每名已显示玩家都返回自己的完整批准字段和观察时间，同一玩家的字段共享该观察时间，服务端不因任一玩家的数据年龄拒绝或标记整个列表，面板可以对单个玩家提示数据可能过期。
  - Given 某个可选在线玩家值在本次有效观察中不可用，When 用户打开该玩家详情，Then 面板将该值显示为未知，其他有效字段仍可查看。
  - Given 一名玩家具有有效跨平台身份并产生多次 Save 观察，When Owner 查询历史详情，Then 面板按稳定身份返回倒序只读快照，并明确显示观察时间、计划内降采样和任何非计划缺口；Given 缺少跨平台身份，Then 该观察仍可用于在线列表但不会产生历史记录。
  - Given 历史队列满、SQLite 暂时不可用或正常关服未能在截止时间排空，When 后续快照成功保存，Then Owner 能看到受影响时间范围、原因和丢失观察数，且在线投影和游戏主线程不因历史写入等待或失败而回滚。
  - Given 用户查看同一份在线玩家结果中的列表和详情，When 页面呈现坐标、距离或时间统计，Then 坐标和距离可以按整数显示，时间可以转换为易读时长，但底层数值语义仍分别是米和分钟。
  - Given 玩家在线，When 具备权限的管理员执行踢出并确认，Then 游戏内玩家被踢出，面板显示成功结果并写入审计记录。
  - Given 游戏已经就绪且命令已由 7DTD 注册，When `Owner` 或 `Admin` 从网页提交服务端自带或第三方 Mod 命令，Then 请求按队列顺序在游戏主线程执行并返回该次调用的输出；Given 命令未注册，Then 返回可识别的未知命令结果而不伪造成功。
  - Given 多个网页命令并发提交，When 队列仍有容量，Then 每个请求独立等待并按接收顺序执行；Given 队列已满，Then 新请求被明确拒绝且不会进入游戏主线程。
  - Given SQLite 或命令审计消费者不可用，When 任一来源执行控制台命令，Then 命令仍按原控制台语义执行，系统产生审计不可用告警，并把受影响时段标记为审计可能不完整。
  - Given 动作执行失败或连接中断，Then 面板显示失败，不能伪造成功，并允许用户重试。
  - Given 用户无相应权限，Then 管理动作不可执行，且网络地址、位置、身份关联和权限等级等敏感玩家数据不会返回或显示。
  - Given 实时连接在事件保留窗口内断开后重连，When 客户端提交最后已确认游标，Then 服务端补发缺失事件且不重复已确认事件；Given 缺失事件已超出保留窗口，Then 客户端收到明确缺口而不是伪造连续记录。
  - Given `Owner` 或 `Admin` 打开控制台页面，When 最近日志快照与实时事件在加载期间重叠，Then 页面按服务端顺序显示每条日志一次，并继续接收新日志；Given 最近快照不可用但实时连接可用，Then 页面明确缺少历史上下文并继续显示新日志。
  - Given 用户滚动离开日志底部，When 新日志到达，Then 页面保持当前阅读位置并累计未查看数量；When 用户选择“回到最新”，Then 页面滚动到底部、清除计数并恢复自动跟随。
  - Given 用户清空当前页面会话，When 实时连接继续，Then 当前已显示日志被清除且新日志仍正常到达，服务端日志窗口、实时游标和审计记录不受影响；When 用户离开后重新进入页面，Then 页面重新读取服务端最近日志。
  - Given 当前进程注册了内置或第三方命令，When `Owner` 或 `Admin` 输入第一个命令词，Then 页面按名称和别名提供动态建议并可用 Tab 补全；Given 动态目录不可用，Then 自由输入与提交仍保持可用。
  - Given 网页命令请求成功，When 服务端返回本次独立输出，Then 页面不把该输出或本地命令行插入原始日志区；Given 请求失败或结果未知，Then 页面以短暂反馈说明状态并保留输入供用户修正或重试。
  - Given `Viewer` 或未认证用户访问控制台页面、最近日志或动态命令目录，Then 服务端和页面都拒绝访问；`Viewer` 仍可按其他能力的授权读取非控制台生命周期状态，但不能通过共享实时连接接收 `console-log`。

### CAP-03: 计划备份与恢复

- **用户结果：** 服主可以无人值守地保护服务器数据，并在需要时按明确流程恢复。
- **Priority:** P0
- **Requirements:**
  - 用户可以启用、停用和查看计划备份，查看最近一次成功、失败及进行中的状态。
  - 用户可以手动触发备份，并在备份完成或失败后获得明确反馈。
  - 用户可以从可用备份发起恢复；恢复前必须明确提示服务器将停止且需要重启，并要求确认。
  - 恢复采用待执行流程：校验备份、记录待恢复状态、安全停止服务器，并在下一次启动且世界加载前应用备份。
  - 恢复失败或被中断时，面板显示状态并保留可追踪的结果，不宣称已恢复。
- **验收标准：**
  - Given 计划已启用，When 到达计划时间，Then 系统执行备份并显示成功或失败结果。
  - Given 存在有效备份，When 用户确认恢复，Then 系统记录待恢复状态、安全停止服务器，并明确提示需要重启。
  - Given 存在待恢复状态，When 服务器下次启动，Then 系统在世界加载前应用指定备份，并在面板恢复可用后显示最终结果及所用备份。
  - Given 没有可用备份，Then 恢复入口不可提交，并说明原因。

### CAP-04: 公告与基础自动化

- **用户结果：** 服主能减少重复广播和固定时段提醒，不必持续在线操作。
- **Priority:** P0
- **Requirements:**
  - 用户可以从网页向游戏内发布即时公告，并看到发送结果。
  - 用户可以配置定时公告和首版固定事件触发器，包括玩家进服欢迎语、周期提醒和血月前提醒。
  - 自动化任务可以启用、停用和查看最近执行结果；失败时不得静默吞掉。
  - 自动化执行遵守管理员配置的时间和目标服务器范围。
- **验收标准：**
  - Given 公告内容有效，When 用户发布公告，Then 在线玩家可见公告，面板显示发送结果。
  - Given 定时任务已启用，When 触发时间或事件到达，Then 公告只发送一次并记录执行结果。
  - Given 任务执行失败，Then 面板显示失败原因并保留重试或人工处理线索。

### CAP-05: 管理员权限与审计

- **用户结果：** 服主能使用可跨重启保留的管理身份登录网站，为自动化创建可独立撤销的 API Key，并在争议或异常发生后追溯责任。
- **Priority:** P0
- **Requirements:**
  - 身份迁移过渡期继续以 `config.json` 中的 `username` 和 `password` 作为现有登录入口；系统每次启动都把这组配置同步到唯一的引导 `Owner`，其身份标识固定为 `owner`，配置变化不得创建第二个引导用户。
  - 网站登录必须针对当前持久用户记录验证用户名和密码，并从该用户的当前状态重建身份声明；产品不得通过 Basic Authentication 接受用户名和密码。
  - 网站登录签发默认有效期 8 小时、不透明且可撤销的 Bearer Access Token，并向浏览器返回服务端确认的当前用户名和角色；浏览器登录后的 API 与实时连接只使用该 Token，不提供 Cookie 会话、CSRF Token 或 refresh token。
  - 登录页提供默认不选中的“保持登录”选项。未选择时，当前标签页在刷新后恢复会话，关闭该标签页后不再保留；选择后，同一浏览器在关闭标签页或重启后仍可恢复会话。两种会话都不得超过 Token 原到期时间，且登出、到期或服务端拒绝身份后必须清除。
  - 认证后的应用壳显示服务端确认的当前用户名和角色。用户名和角色只用于向用户说明当前身份，不能替代服务端对 Bearer Token、用户状态和当前角色的复验。
  - 已登录用户可以创建、列出和撤销自己的 API Key。完整 API Key 只在创建成功时返回一次，后续只能查看名称、安全标识、创建时间、最后使用时间、到期时间和状态；丢失后只能撤销并重新创建。
  - API Key 绑定创建者并继承创建者的当前角色，不保存独立角色副本；创建者被禁用后其 Key 必须失效，创建者角色变化后 Key 权限必须同步变化。API Key 不得用于创建另一把 API Key。
  - Access Token 与 API Key 都只能通过 `Authorization` Header 携带。用户被禁用、凭据被撤销或凭据已过期时，所有后续认证必须失败关闭；已经建立的认证实时连接也必须在下一次复验边界关闭。
  - 过渡阶段不提供用户管理能力；该能力以后落地并能够安全维护至少一个 `Owner` 后，才移除 `config.json` 对引导 `Owner` 的同步职责。
  - 首版管理角色为 `Owner`、`Admin` 和 `Viewer`；`Viewer` 是管理面板只读角色，不代表未来可能加入的玩家身份。
  - 生产 API 和实时连接必须在返回受保护数据前验证管理身份；认证失败和权限不足使用一致、可追踪且不泄露账号存在性或内部异常的错误响应。
  - 只有 `Owner` 可以在独立确认后启动预配置的服务器重启脚本，或发起固定的安全关服操作；两项操作都不得接受浏览器提供的命令、路径、参数或环境值。
  - 重启脚本启动、固定关服及其失败或结果未确认状态都必须独立留有可追溯的操作记录；脚本已启动不得作为服务器已经重启成功的结论。
  - 所有改变服务器或玩家状态的网页操作、自动化动作和恢复操作都可追溯。
  - 审计记录可按时间、操作者、目标和动作检索；记录不可用时明确提示。
- **验收标准：**
  - Given 服务首次启动或重启，When 配置有效，Then 系统创建或更新同一个身份标识为 `owner` 的引导 `Owner`；即使配置用户名或密码发生变化，也不会创建第二个引导用户。
  - Given 服主提交有效的配置凭据，When 通过网站登录，Then 系统针对持久用户记录完成验证，签发默认有效期 8 小时的不透明 Access Token，并返回服务端确认的用户名和角色；Given 客户端改用 Basic Authentication，Then 请求不会建立认证身份。
  - Given 用户登录时未选择“保持登录”，When 刷新当前标签页，Then 会话在 Token 有效期内恢复；When 关闭该标签页后重新访问，Then 用户需要重新登录。
  - Given 用户登录时选择“保持登录”，When 关闭标签页或重启浏览器后重新访问，Then 会话在 Token 有效期内恢复，并在应用壳显示服务端确认的用户名和角色。
  - Given 任一浏览器会话已到期、用户主动退出或服务端对受保护请求返回身份无效，When 用户继续访问受保护页面，Then 浏览器清除已保存会话并要求重新登录，不自动重放状态变更请求。
  - Given 已登录用户创建 API Key，When 创建成功，Then 完整 Key 只在本次结果中返回；Given 用户稍后列出 Key，Then 结果只包含元数据且不能恢复完整 Key。
  - Given 用户使用自己的 Access Token，When 创建、列出或撤销 API Key，Then 只能管理自己的 Key；Given 使用 API Key 尝试创建另一把 Key，Then 请求被拒绝。
  - Given API Key 的创建者被禁用或角色发生变化，When 该 Key 再次请求受保护资源，Then Key 失效或按创建者当前角色授权，不保留创建时权限。
  - Given Access Token 或 API Key 出现在 QueryString、Cookie 或其他非 `Authorization` Header 位置，When 请求受保护资源，Then 该凭据不会建立认证身份。
  - Given 用户已禁用或 Access Token/API Key 已撤销或过期，When 请求受保护 API 或到达认证实时连接的复验边界，Then 请求被拒绝或连接被关闭，且不会继续返回受保护数据。
  - Given 普通访问者无管理权限，When 其尝试执行管理动作，Then 操作被拒绝且不改变游戏状态。
  - Given `Owner` 明确确认启动重启脚本或关闭服务器，When 系统接受该请求，Then 页面只显示该项操作自己的已接受、完成、失败或结果未确认状态，并保留操作记录；重启脚本启动不会显示为服务器重启成功。
  - Given `Admin`、`Viewer` 或未认证访问者尝试启动重启脚本或关闭服务器，Then 请求被拒绝，且服务端不接收任何浏览器命令文本或其他启动参数。
  - Given 请求缺少、携带无效或已过期的管理身份，When 请求受保护 API 或生产实时连接，Then 服务端在返回任何受保护数据前拒绝请求，并提供可关联排查的错误标识。
  - Given 管理动作成功或失败，Then 审计记录包含操作者、目标、时间、动作和结果。

### CAP-06: 游戏聊天管理

- **用户结果：** 服主可以在网页中实时查看和发送游戏聊天、追溯历史记录，并安全配置聊天记录与彩色聊天规则。
- **Priority:** P0
- **Requirements:**
  - “游戏聊天”只允许 `Owner` 访问，包含实时聊天、历史聊天、聊天设置和彩色聊天四项入口；`Admin`、`Viewer` 和未认证用户不能通过页面、REST 或共享实时连接读取聊天内容或修改聊天行为。
  - 实时聊天显示服务端观察到的 UTC 时间、发送者、可用的稳定跨平台身份、运行期实体标识、频道、来源类型和纯文本正文，并区分全局、好友、队伍、私聊和未知频道。
  - 实时连接断开后应按可用游标补取；无法补齐时明确显示聊天缺口，不把不连续记录呈现为完整历史。
  - `Owner` 可以发送 1 至 500 个字符的全局消息，或选择当前在线且具有稳定跨平台身份的玩家发送私聊；提交失败或结果未知时保留输入并允许人工重试，不能自动重放。
  - 历史聊天按 UTC 时间倒序提供有界游标分页，并可按跨平台身份、发送者、频道、来源和时间范围筛选；空结果正常返回，查询失败不得清除最后成功结果。
  - 聊天历史写入不得等待 SQLite 或阻塞游戏主线程；队列满、持久化失败和关服排空超时必须形成可识别的历史缺口，不能影响原始游戏聊天继续发送。
  - `Owner` 可以启停新的聊天捕获和面板主动发送，配置服务端全局/私聊显示名称、单字符命令前缀、命令是否排除历史以及 `0..3650` 天保留期；`0` 表示不自动清理，关闭功能不会删除已有历史。
  - 彩色聊天支持全局、私聊、好友、队伍、管理员和系统消息默认颜色，以及按稳定跨平台身份维护玩家专属名称模板、名称颜色、正文颜色和运营备注。
  - 玩家名称模板只支持 `{playerName}`、`{playerId}`、`{entityId}` 和 `{chatType}`；产品不得执行表达式或脚本。玩家颜色标签权限只允许 `None`、`AdminOnly` 或 `All`，其他富文本标签必须被拒绝或转义。
  - 命令消息绕过彩色重写。彩色重写成功时游戏内只能出现一条替换消息；任何解析、Profile、模板或发送异常必须放行原始消息，不能让扩展功能中断基础聊天。
  - 历史记录保存着色前的原始语义正文；Web 页面始终以纯文本渲染，不执行游戏 BBCode、HTML、Markdown 或链接。
  - 面板发送消息、修改聊天或彩色设置以及创建、修改、删除玩家 Profile 必须留下操作审计；发送审计不保存完整消息正文。
- **验收标准：**
  - Given `Owner` 打开实时聊天，When 最近上下文请求与实时事件发生重叠，Then 页面按服务端 sequence 合并并只显示一次；Given 事件窗口无法补齐，Then 页面显示明确缺口。
  - Given `Owner` 发送有效全局消息或向仍在线的稳定身份发送私聊，When 游戏接受发送，Then游戏内出现对应消息且页面显示已接受；Given 目标离线、队列满、游戏未就绪或结果未知，Then 页面保留输入、显示可区分结果且不自动重试。
  - Given 聊天历史存在多种玩家、频道、来源和时间，When `Owner` 组合筛选并继续加载，Then 服务端按稳定 cursor 返回无重复的倒序结果；Given 首次请求失败，Then 显示错误，Given 刷新失败，Then 保留最后成功结果并标记过期。
  - Given 聊天持久化队列满或 SQLite 写入失败，When 玩家继续发言，Then游戏聊天和实时事件继续工作，历史查询显示或关联到可识别缺口，不伪造连续记录。
  - Given `Owner` 保存或重置聊天设置，When持久化成功，Then后续消息立即使用新设置；Given 保存失败，Then页面和运行时继续使用旧设置，不显示已生效。
  - Given 彩色聊天已启用且玩家命中 Profile，When 该玩家发送普通消息，Then名称和正文按批准优先级渲染且只广播一次；Given消息是命令或彩色处理异常，Then原版消息继续且不发生重复广播。
  - Given 任意聊天正文、名称模板或 Profile 备注包含 HTML、BBCode 或脚本式内容，When Web 页面显示数据，Then仅显示纯文本；未经权限策略允许的游戏颜色标签不会成为可执行或任意富文本。
  - Given `Admin`、`Viewer` 或未认证用户访问任一聊天页面、接口或共享实时事件，Then服务端拒绝或过滤聊天数据，且前端不显示导航入口。

## 核心用户旅程

1. 服主部署 Mod DLL，并以 `config.json` 中的引导 `Owner` 凭据登录；网站获得默认有效期 8 小时的 Access Token，按用户选择在当前标签页或同一浏览器中恢复会话，并显示服务端确认的当前用户名和角色。
2. 面板自动识别当前服务端，验证可管理状态，并展示服务器运行状态和在线玩家。
3. 服主可以在面板创建一次性显示的 API Key，供脚本或第三方集成按其当前角色访问同一受保护接口，也可以独立撤销该 Key。
4. 服主通过网页查看日志、实时处理游戏聊天、发布公告或处理玩家管理事件。
5. 服主开启计划备份，确认最近一次备份成功。
6. 服务端异常或数据问题发生时，服主查看备份状态并确认恢复；面板展示恢复结果和审计记录。

## 产品级约束

### NFR-01: 自托管与数据控制

- **Requirement:** 首版产品可由服主自行部署，服务器管理数据和备份数据不要求上传到第三方云端才能使用核心能力。
- **Verification:** 在无产品方托管服务的环境中完成 Mod DLL、网页面板及核心 P0 能力的部署和验收。

### NFR-02: 操作安全与状态诚实

- **Requirement:** 高风险操作需要确认；连接中断、任务失败、状态超过批准的新鲜度窗口和恢复未完成必须对用户可见，系统不得将未知、部分或过期状态显示为已确认新鲜。过期的最后已知数据可以成功传输和继续展示，但必须保留真实采样时间及明确的过期标记。主机身份、系统用户、公网地址、卷根路径和同类敏感主机字段必须按服务端角色裁剪；浏览器不得提交任意命令、脚本路径、参数或环境值。脚本进程已启动只能表示启动动作被接受，不等于服务器重启成功。
- **Verification:** 对权限拒绝、网络中断、首次数据超时、状态过期、部分可用、重复提交和恢复失败场景执行验收测试。验证不同角色取得的敏感主机字段、危险确认与任意命令输入拒绝，以及脚本启动后的页面文案不会声明服务器已经重启成功。Given 在线玩家状态超过批准窗口，When 客户端刷新列表，Then 服务端返回最后已知投影并标记过期，客户端进入明确的 Stale 状态、继续展示可用数据且不显示 Fresh。

### NFR-03: 简体中文与英文一致体验

- **Requirement:** 首版管理面板支持 `zh-CN` 和 `en`。首次访问优先使用受支持的浏览器语言，不受支持时回退到 `en`；用户可以在登录前和登录后切换语言，选择结果作为非敏感偏好保存在当前浏览器。切换语言不得清除可安全保留的表单输入，产品文案、组件内置文案、表单校验错误、日期与数字格式以及由服务端错误码映射的用户消息必须使用同一当前语言；Steam ID、审计标识、路径、日志原文和协议标识等技术内容保持原样。
- **Verification:** 在 `zh-CN` 和 `en` 下分别完成全部 P0 流程，验证浏览器语言匹配、默认回退到 `en`、登录前后切换与持久化、多表单内置校验错误、服务端错误码映射、日期与数字格式，以及切换前后安全表单输入的保留行为。

### NFR-04: 过渡持久身份与传输边界

- **Requirement:** 身份迁移过渡期允许发布模板和缺失配置时生成的 `config.json` 默认提供 `admin` / `password`，并以 `allowInsecureHttp=true` 接受明文 HTTP 上的网站密码登录；该已知凭据和明文传输风险属于当前阶段明确接受的运行假设。每次启动必须把配置凭据同步到身份标识固定为 `owner` 的唯一引导 `Owner`，网站登录必须验证该持久用户的当前状态，且所有接口都不得接受 Basic Authentication。默认 8 小时的网站 Access Token 和用户创建的 API Key 必须是不透明、可撤销的 Header-only Bearer 凭据，不得进入 URL、Cookie、产品日志、错误详情、前端构建产物或版本库；网站 Access Token 仅可按 `CAP-05` 进入用户选择的浏览器会话存储，密码和完整 API Key 不得进入任何浏览器持久状态。完整 API Key 只允许在创建结果中显示一次。产品不采用 Cookie 认证，不提供 CSRF Token 或 refresh token。配置缺失、解析失败、用户禁用、凭据无效、撤销或过期以及授权失败均不得退化为匿名访问。用户管理能力进入发布范围并能够安全维护至少一个 `Owner` 后，必须移除配置引导身份和已知默认凭据，并恢复加密传输要求。
- **Verification:** 检查 `config.example.json`、缺失配置时生成的 `config.json` 和运行时选项保持同一过渡默认值；验证每次启动只创建或更新同一个引导 `Owner`，配置用户名或密码变化后旧凭据失效且不会产生第二个引导用户；验证网站密码登录根据持久用户当前状态建立身份，而 Basic Authentication 在 API 与实时连接上均被拒绝。验证 Access Token 和 API Key 仅通过 `Authorization` Header 生效，无效、撤销或过期凭据、禁用用户、QueryString 凭据、Cookie 凭据和权限不足均被拒绝；验证未选择和选择“保持登录”时分别使用当前标签页会话和浏览器持久会话，损坏、到期、登出或 401 后均清除，且密码、完整 API Key 和 Bearer 文本不进入非认证浏览器状态、URL、日志或错误详情；验证完整 API Key 只出现一次且不会进入后续列表或前端持久存储；认证实时连接必须在心跳或凭据有效期边界复验，并在失效时关闭。未来移除配置引导身份的发布门禁必须重新验证发布物无可登录默认凭据，并在 HTTPS 或受控本机反向代理链路上完成认证实时连接验收。

### NFR-05: 服务器本地文件信任边界

- **Requirement:** 能够读取 7DPanel 所在服务器本地文件系统的主体视为受信任运维者；首版不以防止该主体读取、复制或离线分析 `config.json`、SQLite 数据库、备份和服务端日志为安全目标，也不承诺这些本地文件静态加密。该边界不扩大到网络客户端、浏览器、前端生产资产、版本库或产品日志/API 响应中的意外披露：不具备服务器本地文件读取权限的主体仍不得通过产品接口取得配置凭据、有效 Token 或未授权管理数据。
- **Verification:** 安全审查不把服务器本地文件读取者获得配置或 SQLite 内容判定为产品漏洞；继续验证发布物和版本库不包含服务器自有 `config.json`、运行时数据库或有效凭据，API、错误详情、前端资产和产品日志不向网络客户端泄露配置凭据或有效 Token，受保护资源仍执行认证与授权。

## 假设与依赖

- 随服务端运行的 Mod DLL 通过 7DTD 提供的 Mod 事件和游戏管理能力完成首版所需的状态、玩家、日志、公告和保存操作；版本兼容范围以运行时验证结果为准。
- **假设：** 首版以单服务器为主要使用场景；多服务器管理不影响首版核心合同。
- **依赖：** 7DTD 服务端版本、Mod 加载机制和可用的游戏接口会影响能力覆盖范围。
- **依赖：** 完成恢复需要服务器进程在安全停止后重新启动；首版允许由服主或其现有进程管理工具执行重启。
- **假设：** 首版身份认证和管理员权限由自托管面板提供；持久化、迁移和运行时边界由后端架构文档负责。
