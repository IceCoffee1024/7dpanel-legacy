# 7DPanel 产品设计

本文档定义目标版本网页管理面板的信息架构、核心流程、界面状态与视觉规则。产品范围由[产品需求文档](PRD.md)定义，当前技术实现由[系统架构](architecture.md)定义，旧版本功能对齐的分阶段边界见[目标蓝图](architecture/legacy-feature-parity-target-blueprint.md)，验证要求见[测试策略](test.md)。

当前 `frontend/apps/admin/` 已实现独立 `/login` 与受保护的概览、在线/历史玩家、玩家地图、游戏资源、控制台日志、游戏聊天、审计与游戏事件、访问名单、服务器配置、模组、权限、API Keys，以及六波次新增的备份、调度、玩家 Profile/动作、经济/奖励/商业、Community、Automation、Discord、GeoIP、世界工具和功能模块路由。精确实现与验证边界仍以[系统架构](architecture.md)和[测试策略](test.md)为准；页面存在不表示真实游戏、外部服务、危险世界操作或浏览器 E2E 已验收。

### 当前 Admin 纵向切片

- 匿名访问 `/`、`/players` 或 `/api-keys` 时进入 `/login`，并在查询参数中保留安全的站内返回目标；登录页刷新后保持登录页。登录成功后进入原目标：默认“保持登录”不选中，刷新当前标签页会恢复会话而关闭该标签页后需要重新登录；选择后可在同一浏览器关闭标签页或重启后、原 Access Token 到期前恢复。浏览器 Storage 不可用时保持当前页登录并显示非阻断提示。
- 认证后的侧栏和搜索入口只显示已实现且当前角色可达的页面；第一波新增的“审计与事件”和“禁言管理”只对 `Owner` 显示，分别进入 `/audit` 与 `/game-chat/mutes`。`Admin`、`Viewer` 的直接深链接进入 Forbidden，匿名深链接保留安全返回目标后进入登录页。账号入口显示服务端确认的当前用户名和角色，并提供退出登录；退出、到期、401 或其他标签页删除会话后立即离开受保护页面。
- 六波次管理入口只对 `Owner` 展示。侧栏把 `/world-tools`、`/modules`、`/backups`、`/schedules`、`/automation` 归入“服务器运维”，把八个 `/economy/*` 页面（含 `/economy/daily-reward`）归入“经济与奖励”，把 `/community/teleport|cities|votes` 归入“传送与投票”，把 `/integrations/discord|geoip` 归入“集成与访问策略”；Dashboard Search 复用同一组可达 child，不维护第二份路由目录。
- 新管理页面继续使用薄 route page、Feature 内严格 parser 和 readonly composable。写操作等待服务端结果，不做乐观成功；`Queued`、`Running`、`PendingReconciliation`、`ResultUnknown`、`ActionResultUnknown`、Stale、Forbidden 和 unavailable 都以独立状态呈现。后端缺少全量列表合同时显示稳定 unavailable，不用浏览器缓存或假数据补合同。
- `/economy/daily-reward` 只向 `Owner` 展示唯一 `daily` 规则的奖励包绑定与启用状态。页面把未配置、加载、保存中、已保存、冲突、权限不足和不可用明确区分；版本冲突保留表单草稿，不把保存请求或领取结果乐观显示为成功。
- `/community/cities` 显示全部城市而不是只显示启用项。每张城市卡明确标识启用或停用状态；创建和编辑仍使用同一个受控表单，保存成功后刷新全量列表，保存失败保持当前可见数据与表单上下文。
- `/community/teleport` 同时提供规则设置、按玩家/双方/操作 ID 的直接核对，以及完整好友记录和传送操作历史。完整列表与直接查询各自显示 Loading、Empty、Forbidden、Unavailable 或 Stale，互不覆盖，也不因一个查询失败而隐藏另一个结果。
- `/community/votes` 把所有投票轮次的历史与仍等待动作执行的 `ActionQueued` 子集分开显示；按 ID 的单轮核对和结算仍保留。城市保存或投票结算确认成功后刷新对应全量列表；失败或未知结果不触发伪刷新。
- 世界工具提交前重新读取世界、世界版本和地图资源版本，并在 URL 中保存 `operationId` 以支持刷新恢复。撤销变更集时，用户只提供源操作 ID；Admin 先执行只读 undo preflight，只读展示服务端确定的变更集、世界版本和区域匹配结果，且仅在当前区域哈希匹配时允许进入强确认。功能模块只对可切换项显示启停确认，健康证据缺失时显示 `Unknown`。危险世界操作的 UI 可存在，但真实 smoke 必须先确认测试实例、备份和回滚目标。
- `/players` 的桌面布局使用全宽紧凑表格展示名称、entity ID、存活/生命、等级、延迟、设备和逐玩家更新时间；窄屏列表保留玩家、状态、等级、延迟、更新时间与详情入口，不依赖横向滚动。完整身份、IP、位置和累计统计只在详情抽屉展示；可复制的身份和 IP 提供明确入口，抽屉内提供可达的刷新操作并以 `alert` 语义报告目标不可用。
- 桌面表格和移动列表为每名玩家提供固定尺寸的详情与踢出图标操作。详情从右侧打开，按身份、连接、当前状态、累计统计分区展示完整 observation；所有传输空值显示“未知”，坐标和距离以当前语言整数显示，分钟统计显示为可读时长。详情以 entity ID 加原生身份锁定：Fresh 刷新只更新同一身份，缺失或身份变化时保留最后 observation 并提示不可用、禁用踢出直到关闭。确认对话框固定打开时的玩家名、平台和主身份，详情或轮询更新不会替换目标；原因 trim 后必须为 1 至 200 个字符，提交期间输入、取消、关闭和确认全部锁定。
- 踢出成功后关闭对话框、显示包含固定玩家名的成功通知并立即刷新。玩家离线、身份变化或提交后 403 会关闭旧目标并阻止再次提交；busy、游戏未就绪、主线程超时和审计意图不可用保留原因供显式重试；网络与审计完成不可确认显示“结果尚无法确认”且不自动重试。
- 首次查询显示稳定骨架；空结果直接说明当前没有可显示玩家；成功响应展示每个玩家自己的最后观察时间，Admin 对超过 90 秒的玩家行标记“数据可能已过期”；刷新失败继续保留上一结果并提示“刷新失败，显示上次结果”；无可用结果时显示不可用及重试；403 显示无权状态；401 清除会话并返回登录页。
- API Keys 页面只使用当前网站 Access Token 的 `Authorization` Header：完整 Key 仅在创建结果对话框中显示并可复制，关闭即清除；列表、撤销确认和反馈只使用安全元数据，API Key 身份不能创建或撤销 Key。401 清除会话并返回登录页，403 显示无权状态，加载、创建和撤销失败保留可安全重试的页面状态。
- `/game-resources` 位于“玩家与世界”导航组并可由 Dashboard Search 或 `g-r` 进入。`Owner`、`Admin`、`Viewer` 都能读取公开目录；只有 `Owner` 看见“包含隐藏资源”筛选。页面以 URL 保存搜索、item/block 类型、隐藏筛选和分页，桌面使用表格，窄屏使用单列条目；图标只通过 Header Bearer Blob 加载，Token 不进入 URL。
- 当前 `/` 的游戏分区使用独立运行指标面板展示十一项指标。每项保留值、单位、来源、观察时间和可选 warning；分区不可用时不绘制伪造零值，刷新失败保留上次成功采样并明确标为 Stale。
- `/audit` 以“统一审计”和“游戏事件”两个标签组织只读查询。审计按 UTC 时间、操作者、目标、动作、来源和状态筛选；游戏事件按 UTC 时间、类型和跨平台身份筛选。两者分别展示来源 gap 与游戏事件 gap，不把 gap 混入正常记录。
- `/game-chat/mutes` 提供游标分页的当前禁言列表，桌面使用表格、窄屏使用单列卡片；创建和编辑共用表单对话框，解除使用独立确认对话框。永久禁言与 UTC 截止时间明确区分，提交期间锁定重复操作，成功后刷新权威列表而不做乐观成功。
- 审计、游戏事件和禁言数据都先经过 Feature 的严格 Valibot parser。首次请求显示骨架，空集合显示正常空状态；首次请求或协议校验失败进入 Failed。普通刷新或继续分页时，已有成功结果可在请求或协议失败后保留并进入 Stale；应用新筛选会先清空旧页，失败时进入 Failed。403 进入 Forbidden，401 清理会话并回到登录页。未通过 parser 的 payload 不进入表格、列表或卡片。
- 运行指标文案已接入当前 i18n；审计、游戏事件和禁言页面仍存在直接写入的中文可见文案，因此本切片不能宣称 `NFR-03` 双语合同已经闭环。
- 第一波审计/游戏事件/禁言组件与状态机已有定向自动化；六波次新增页面、分组导航、Dashboard Search 与 Owner-only route meta 已有代码证据，最终 Admin typecheck、AppShell/router/i18n/Community 聚焦测试和 JSON key audit 已由主线程执行并通过。world-tools/modules/player-map 的完整聚焦组合、定向 lint，以及真实 OWIN 下的 `390x844` 渲染、重叠和水平溢出检查仍未执行，不能用现有静态证据替代这些边界。

### Admin 综合概览第一阶段

以下保留已批准的第一阶段设计。第一波已经在当前 `/` 的既有综合概览中加入十一项运行指标呈现；指标面板及其 Unavailable/Stale 状态是当前事实，本节其他目标是否已实现仍以[系统架构](architecture.md)的代码证据为准，不能只从设计条目推导。

页面信息按下列层级阅读，前一层优先回答服主是否需要处理，后续分区保留各自的真实状态和采样时间：

1. **顶部状态**：面板、游戏与综合快照的新鲜度，及可立即判断的运行摘要。
2. **服务器信息**：服务器、世界、连接与游戏侧基础信息。
3. **主机平台**：操作系统、运行时、设备与进程身份；敏感身份信息按角色裁剪。
4. **资源容量**：内存、磁盘及其他容量摘要与可用明细。
5. **注意事项**：按严重程度排列的待处理项，正常时显示紧凑空状态。
6. **近期活动**：安全摘要、相对时间和精确发生时间。
7. **重启策略**：只读的安全摘要与下一次计划信息；配置编辑继续留在独立页面。
8. **快捷操作**：重新采样、Owner 专属的重启脚本启动，以及固定的关闭服务器操作。

第一阶段的首页状态为：

| 状态 | 展示与交互规则 |
|---|---|
| `Loading` | 首次综合请求尚未完成，各分区使用骨架，不伪造零值。 |
| `Fresh` | 最新综合快照在批准的新鲜窗口内，显示各分区实际采样时间。 |
| `Partial` | 综合请求成功但至少一个分区不可用或无权读取；其他分区继续展示，受影响分区说明原因。 |
| `Stale` | 保留最后成功快照、原采样时间和过期标记，不显示为 Fresh。 |
| `Offline` | 没有可用综合快照或接口不可达；单一游戏字段缺失不能单独推导此状态。 |
| `RestartScriptStarted` | 仅提示重启脚本已启动、服务器连接可能中断；不得显示“服务器已重启成功”。 |

设备标识、当前系统用户名、公网地址、卷根路径和网卡身份等字段只在服务端已确认的 `Owner` 响应中展示。`Admin` 与 `Viewer` 只能获得经裁剪的内容和明确的不可用或无权状态；前端隐藏不能替代服务端授权。

“启动重启脚本”与“关闭服务器”都是危险操作，分别使用独立的确认界面、固定目标和提交状态，不能共享一次确认或复用结果文案。确认按钮使用具体动作名称。两者都不接收浏览器命令、脚本路径、参数或环境值；重启脚本启动后只报告启动状态，固定关服则按其自身的已接受、完成、失败或结果未确认状态反馈。

## 信息架构

### 设计原则

- **先回答“服务器现在是否需要处理”**：登录后的第一屏优先展示连接、运行、在线人数、最近备份和失败任务，而不是宣传内容或装饰性数据。
- **围绕事件处置组织信息**：玩家、日志、任务和审计之间保留可追踪入口，减少服主在多个页面重复搜索目标。
- **状态诚实优先于即时反馈**：成功、失败、排队、处理中、结果未知和状态过期必须可区分，并显示采样或更新时间，满足 `NFR-02`。
- **默认面向单服**：首版不显示服务器切换器或多服总览，页面标题区域固定展示当前 Mod 所在服务器的名称和连接状态，符合 `CAP-01`。
- **高频操作短路径，高风险操作有摩擦**：查看、筛选和安全操作保持直接；封禁、恢复等高影响动作必须明确确认。
- **同一语言贯穿完整任务**：产品文案、组件内置文案、表单校验、日期数字和可操作错误必须随当前语言一致切换，避免同一流程中中英文混杂，落实 `NFR-03`。

### 入口与全局框架

未认证入口只有两个：

1. 引导 `Owner` 已从 `config.json` 成功同步时进入登录页；页面不展示已知默认凭据，用户使用服主维护的当前配置凭据登录。
2. 认证配置缺失、无效或引导 `Owner` 同步失败时进入“需要配置”状态；页面说明必须在服务端修复 `config.json` 并重新加载，不提供匿名降级、浏览器内创建用户或远程重置入口。

登录页和“需要配置”状态均提供语言选择器。首次访问优先匹配浏览器支持的 `zh-CN` 或 `en`，其他语言回退到 `en`；选择后立即更新当前页面、关闭选择菜单并保存在当前浏览器。

认证后的全局框架包含：

- **桌面主导航**：固定侧栏按“运行”“玩家与世界”“运营”“系统”分组。目标入口覆盖概览、玩家、玩家档案与物品、地图与世界、游戏聊天、控制台与日志、访问名单、公告与自动化、备份与恢复、经济与奖励、商店与兑换、传送与投票、审计与游戏事件、Discord、GeoIP、服务器配置、模组与功能模块、权限、API Keys 和设置；无权或尚未实现的页面不显示。“游戏聊天”展开实时聊天、历史聊天、禁言、聊天设置和彩色聊天子入口。
- **移动主导航**：由菜单按钮打开抽屉；当前页面名称、服务器状态和紧急告警始终位于顶部区域。
- **全局状态条**：展示连接状态、运行状态、状态更新时间及 draining/离线告警。状态异常时跨页面持续可见。
- **全局任务入口**：展示正在运行及最近失败的备份、恢复和自动化任务；任务完成后可进入对应详情，不只依赖短暂通知。
- **账号入口**：展示当前角色、修改凭据和退出登录；无权访问的导航项隐藏，直接访问仍显示明确的权限拒绝页。
- **语言入口**：在全局框架中持续可达，明确显示当前语言；切换后保持当前路由、筛选和可安全保留的表单草稿。

## 核心流程

### 引导 Owner 登录与配置异常

1. 服务端每次启动都将 `config.json` 中的 `username` 和 `password` 同步到身份标识固定为 `owner` 的唯一引导 `Owner`；配置变化只更新该身份，不创建第二个引导用户。
2. 同步成功后，未认证用户进入登录页并提交当前配置凭据；页面不显示发布模板中的已知默认值，也不把凭据写入 URL 或浏览器持久存储。
3. 提交期间锁定重复提交并显示正在验证；失败信息不区分账号不存在、密码错误、用户禁用或内部身份状态。
4. 登录成功后建立默认有效期 8 小时的 Header Bearer 会话并进入原本有权访问的页面，否则进入概览；未选择“保持登录”时仅在当前标签页恢复，选择后才在同一浏览器恢复。两种方式都不延长 Token 有效期、不自动刷新会话。
5. 配置缺失、解析失败或引导身份同步失败时，页面进入“需要配置”状态，保留不依赖认证的健康信息，并提示服主在服务端修复配置；受保护数据和操作保持不可用。
6. 当前初始化开发阶段不提供初始化码、初始化链接、浏览器内创建首个 `Owner` 或远程重置；登录后的 `Owner` 可以管理其他面板用户，但不能删除、禁用或降权最后一个启用的 `Owner`。
7. 用户管理不改变 `config.json` 引导同步、已知开发默认凭据或明文 HTTP 例外；未来移除任一边界需要独立批准的产品与安全设计。

该流程落实 `CAP-05` 和 `NFR-04`，并保持认证失败关闭。

### 服务器配置

1. `Owner` 进入页面后读取配置字段和文件版本；`Admin`、`Viewer` 与未认证用户进入明确的权限状态。
2. 页面按稳定目录分组展示当前 7DTD 版本的官方字段；当前 XML 中存在但尚未登记的非敏感字段进入“高级”分组并保持可编辑，敏感字段只显示是否已设置，不显示当前值。
3. `Owner` 选择普通字段后使用布尔、枚举、整数、数值或文本控件修改；高级字段使用带明确提示的文本控件。确认界面固定展示字段、旧值、新值和是否需要重启，敏感值不进入确认内容。
4. 提交期间锁定该字段。版本冲突保留输入并要求刷新；失败保留旧配置和读取时间；结果未知时不自动重试。
5. 保存成功后刷新字段版本，并准确显示“立即生效”或“重启后生效”，不把文件写入成功表示为游戏运行时已经采用新值。

该流程覆盖 `CAP-06`、`NFR-02` 和 `NFR-05`。

### 黑白名单

1. `Owner`、`Admin` 或 `Viewer` 进入访问名单页，在封禁与白名单页签间切换；当前页签和搜索条件保存在 URL。
2. 封禁展示玩家 ID、显示名、截止时间和原因；白名单展示玩家 ID 与显示名。永久封禁使用明确文本。
3. `Owner` 和 `Admin` 可以单项新增、编辑或移除；`Viewer` 只读。确认界面固定显示玩家 ID、显示名、动作和后果。
4. 目标不存在、已经变化或游戏未就绪时保留当前列表并说明原因；成功后只刷新受影响名单，不提供批量选择。

该流程覆盖 `CAP-02`、`CAP-05` 和 `NFR-02`。

### 双层权限管理

1. 只有 `Owner` 可以进入权限管理页；页面分为面板用户、游戏管理员和命令权限三个分区。
2. 面板用户分区允许创建用户、调整用户名/角色/启用状态、重置密码和删除用户。密码只写不读，最后一个启用的 `Owner` 不能被删除、禁用或降权。
3. 游戏管理员分区按玩家 ID 维护显示名和 `0..2000` 权限等级；命令权限分区按命令维护原生等级并只读展示当前进程提供的描述。
4. 页面固定说明数值越小权限越高，并说明游戏权限不会改变面板 `Owner`/`Admin`/`Viewer` 或网页控制台授权。

该流程覆盖 `CAP-05` 和 `NFR-04`。

### 模组管理

1. 所有已认证角色可以查看模组名称、作者、版本、描述、当前进程加载状态和下次启动状态；页面不显示服务器绝对路径。
2. 只有 `Owner` 可以切换下次启动状态。确认界面固定展示模组和“重启后生效”，受保护模组不显示可执行入口并说明原因。
3. 保存成功后只更新下次启动状态，不显示已经热加载或卸载；当前进程状态只有在服务器重启并重新读取后变化。
4. 元数据损坏、目录越界或文件操作失败时不改变现有状态，并提供安全错误与审计关联标识。

该流程覆盖 `CAP-06`、`NFR-02` 和 `NFR-05`。

### 登录与会话恢复

1. 用户输入账号和密码并可选择“保持登录”；失败信息不区分账号是否存在。
2. 登录成功后，浏览器只使用默认有效期 8 小时的 Header Bearer Access Token，并采用服务端确认的用户名和角色显示账号信息。未选择时会话只在当前标签页刷新后恢复；选择后可在同一浏览器重启后恢复。浏览器不使用 Basic Authentication、Cookie、refresh token 或 silent refresh。
3. Storage 不可用时成功登录仍保留在当前页面，并提示会话不会在刷新或关闭后保存。登出、到期、401、损坏会话或其他标签页删除会话时停止新操作、清除会话并打开登录界面；403、网络错误、5xx 和 SSE 断开不误清仍可能有效的会话。重新登录后恢复安全返回目标、筛选条件和可安全保留的未提交表单，但不自动重放危险操作。

### API Key 管理

1. 已登录用户进入 API Keys 页面，列表只显示自己创建的 Key 元数据，不显示完整 Key、secret 或摘要。空列表提供单一“创建 API Key”入口。
2. 创建表单要求名称并允许选择到期时间；提交必须使用网站 Access Token，API Key 身份不能创建另一把 Key。
3. 创建成功后打开一次性结果对话框，完整 Key 使用等宽文本展示并提供复制按钮；关闭前明确提示完整 Key 之后无法再次查看。复制成功只反馈复制结果，不把 Key 写入通知、URL、日志或前端持久状态。
4. 一次性结果对话框关闭后，页面只保留安全标识、名称、创建时间、最后使用时间、到期时间和状态；页面刷新不得恢复完整 Key。
5. 撤销操作固定显示 Key 名称和安全标识并要求明确确认。撤销成功后该 Key 立即显示为已撤销且不能重新启用；失败时保留当前列表状态和可关联错误，不伪造成功。
6. 创建者被禁用、角色改变或 Key 到期时，列表状态与后续授权结果保持一致；角色变化不在 Key 列表中复制为可编辑权限。

该流程落实 `CAP-05` 和 `NFR-04`；API Key 用于脚本与第三方集成，不用于恢复浏览器登录会话。

### 日常巡检

1. 用户进入概览，先查看全局状态条和需要处理的异常。
2. 概览按“当前状态、需要处理、近期活动”排列，正常指标保持紧凑，失败任务和过期数据优先呈现。
3. 用户从异常项进入玩家、日志、备份或自动化页面，并保留来源时间范围或目标筛选。
4. 返回概览后刷新相关状态；旧值在新值到达前必须保留原时间戳，不能伪装为实时值。

该流程覆盖 `CAP-01` 和 `NFR-02`。

### 玩家事件处置

当前玩家页只实现以下踢出流程；禁言已经在独立 `/game-chat/mutes` 页面实现，但从玩家行直接发起禁言、封禁、传送、任务回看和专用审计详情仍是目标设计：

1. `Owner` 从桌面或移动玩家动作菜单选择“踢出玩家”。
2. 确认对话框固定显示目标玩家名、平台和主身份；用户填写 1 至 200 个字符原因，明确点击“踢出玩家”。
3. 提交期间对话框不可关闭或重复提交。成功后通知并刷新；离线或身份变化关闭旧目标并刷新；403 关闭旧目标并隐藏动作；可重试错误保留输入；未知结果不显示为失败也不自动重试。

#### 在线玩家列表与详情

当前在线玩家页把列表用于高频比较，把完整观察值放入详情抽屉，不将所有字段横向铺满表格：

1. 桌面主表固定展示玩家名称与 entity ID、存活/死亡与生命值、等级、延迟、设备、逐玩家更新时间和操作；身份全文、网络地址、位置和累计统计不占用主表列。
2. 窄屏列表展示玩家、存活/生命、等级、延迟和逐玩家更新时间，并提供明确的“查看详情”入口；关键阅读和操作在 320 CSS 像素宽度下不依赖横向滚动。
3. 点击玩家行或详情图标从右侧打开详情抽屉；窄屏抽屉占满可用宽度。抽屉标题持续显示玩家名称和存活状态，并按身份、连接、当前状态、累计统计四个无嵌套卡片的分区排列。
4. 身份区展示 entity ID、原生身份、跨平台身份和 Discord ID，身份值提供复制按钮；连接区展示 IP、设备、兼容版本、Ping 和权限等级，IP 提供复制按钮，并说明权限等级数值越小权限越高。
5. 当前状态区展示三轴位置、存活/死亡、当前与最大生命、等级和观察时间；累计统计区展示分数、丧尸击杀、玩家击杀、死亡次数、累计游戏时长、步行距离、制作数量、最长存活时长和当前存活时长。
6. API 保留坐标与距离的原始精度，界面按四舍五入后的整数和当前语言千位分隔显示；分钟型统计转换为可读的天、小时、分钟，并保持分钟语义。所有传输空值统一显示“未知”，不显示 `null`、空白或多个含义相近的占位文案。
7. 抽屉选择状态与踢出确认目标分离，并在底部提供刷新入口。正常情况下，刷新后以 entity ID 和原生身份匹配同一玩家并更新抽屉内容；一旦成功刷新确认玩家离线或身份变化，抽屉锁存最后观察值并以 `alert` 语义显示“玩家已不在线或身份已变化”，禁用危险操作，直到用户关闭抽屉。后续同身份重新出现也不自动恢复该抽屉，避免把新会话当作原目标。
8. 抽屉底部可以发起现有踢出确认；打开确认时固定复制当时的玩家目标，后续列表或抽屉刷新不能替换该危险操作目标。

详情中的踢出入口只在当前查询为 Fresh、玩家详情未锁存为不可用且现有权限允许时启用。Stale、Offline、Forbidden、Session expired 或游戏未就绪时不从旧详情发起新危险操作；请求恢复 Fresh 后，只有尚未锁存不可用的同一玩家详情可以重新操作。

详情抽屉用于只读次要内容，危险确认继续使用阻断式对话框。网络地址、位置、身份关联和权限等级只在服务端已授权的玩家响应中展示；前端隐藏不是授权边界。

完整目标流程如下：

1. 用户在玩家页按名称或可用身份筛选在线玩家，打开行内操作或详情。
2. 选择踢出、禁言、封禁或传送后，确认界面固定展示目标玩家、动作、影响和可选原因，避免误操作到相邻行。
3. 封禁要求更强确认；其他会改变游戏状态的动作至少需要一次明确确认。确认按钮使用具体动作名称，不使用模糊的“确定”。
4. 提交后该动作显示排队或执行中；用户可离开页面，并从全局任务/近期活动回看结果。
5. 成功、失败或结果未知均展示审计关联标识；只有收到权威执行结果后才显示成功。

无权限用户不显示操作入口，也不能看到角色不允许访问的敏感玩家字段。该流程覆盖 `CAP-02`、`CAP-05` 和 `NFR-02`。

#### 历史玩家列表与详情

1. `Owner` 在玩家页的“历史”分区按名称或跨平台身份搜索，并可手动刷新和加载下一页；`Admin`、`Viewer` 和未认证用户进入明确的权限或登录状态。
2. 列表按首次观察时间展示稳定跨平台身份、最近名称、首次/最后观察、总快照数、保留数和数据质量。存在非计划缺口时优先显示“存在历史缺口”；否则有已压缩数据时显示“已降采样”；其余显示“完整”。
3. 点击摘要进入可深链接的玩家详情。详情顶部展示规范跨平台身份、时间范围、保留说明和缺口汇总；时间线按观察时间倒序加载更多，不将不同快照推断为连续在线时段。
4. 每个时间线项只概览名称、实体标识、等级/进度、生命、延迟、位置和累计统计；点击后打开只读详情抽屉。详情按身份、连接、当前状态、进度、累计统计分区展示，玩家组和最近登录位于身份分区，床铺位于当前状态分区。
5. 可空历史字段统一显示“未知”；床铺为空明确显示“未设置”。最近登录时间使用游戏持久玩家记录原义，不以观察时间替代，也不显示持续在线时长。技术身份和缺口原因保持原值。
6. 历史详情没有踢出、禁言、封禁、传送、重置、删除或导出入口。需要处置时，用户必须返回当前在线玩家并重新通过在线身份与可用状态确认。

该流程覆盖 `CAP-02` 和 `NFR-02`。历史页在游戏尚未就绪时仍可以读取本机 SQLite 中已经保存的历史；这不把历史数据表示为当前在线状态。

### 游戏资源目录

1. 三个认证角色从“玩家与世界”导航组、Dashboard Search 或 `g-r` 进入 `/game-resources`；路由不做角色裁剪，服务端仍独立执行目录和隐藏资源授权。
2. 页面首屏读取公开目录，URL 持有非空搜索、`item`/`block` 类型、Owner-only 隐藏开关和页码；空搜索与 `all` 不写入 URL。搜索 250ms debounce，其他筛选立即回到第一页并取消旧请求。
3. 成功页显示目录版本、游戏版本、观察时间、结果总数和分页；每条资源显示认证 Blob 图标或占位、本地化名及内部名、类型、最大堆叠、品质、可见性、tint 色块/六位文本，并提供只复制内部名的操作。
4. `Loading` 使用稳定骨架；`Empty` 提供清除筛选；`Partial` 保留 rows 并显示采集 warning；刷新失败进入 `Stale` 并保留最后成功页和原观察时间；Building 有界自动重试；Unavailable 提供显式重试；Forbidden 不保留隐藏结果。401 仍走全局会话过期处理。
5. 桌面从 `md` 起使用紧凑表格，窄屏使用单列条目而不是横向滚动。隐藏资源不会因当前角色变化继续显示；页面不出现发放、补偿、奖励、商店、删除或自由文本控制台动作。

图标请求只发送 Header Bearer，并在资源、Token、可见性或组件生命周期变化时中止旧请求和释放 Blob URL；`resourceId` 编码进入受控 API 路径，Authorization 值不进入 DOM、URL、日志或持久状态。该页面只证明 `CAP-08` 的资源目录底座，不证明玩家物品档案或物品变更流程已经实现。

### 游戏聊天

“游戏聊天”只对 `Owner` 展示，桌面使用侧栏子导航，移动端使用抽屉中的同级子入口。直接访问 `/game-chat/live`、`/game-chat/history`、`/game-chat/mutes`、`/game-chat/settings` 或 `/game-chat/colored` 时仍由路由和服务端分别校验权限。

实时聊天进入时先注册唯一应用级 SSE 的 `chat-message` 监听，再读取最近 200 条上下文，最后按 `sequence` 合并、升序和去重。顶部频道筛选只过滤页面内存；消息行显示频道、来源、发送者、时间和纯文本正文。位于底部时跟随新消息，离开底部后保持阅读位置并累计未读数；连接、重连和 gap 状态位于消息区外。

输入区默认发送全局消息。选择右侧在线玩家后切换为私聊并固定显示目标身份；目标必须具有稳定跨平台 ID。Enter 发送，Shift+Enter 换行，提交中阻止重复操作。成功后清空输入并进入当前页面最多 50 条发送历史；失败或结果未知保留正文和目标，不自动重试。窄屏把在线玩家列表放入抽屉，不压缩消息阅读区。

历史聊天使用 URL 保存跨平台 ID、发送者、频道、来源、UTC 时间范围和 cursor；查询条件变化时取消旧请求并回到第一页。桌面表格与移动摘要列表均显示时间、发送者、身份、实体 ID、频道、来源和正文。首次失败显示错误，后续刷新失败保留最后成功页并标为 Stale，空集合显示正常空状态。

聊天设置按“功能与发送名称”“命令与历史”分组；彩色聊天按“玩家 Profile”“默认设置”两个标签分组。两类设置都支持保存、恢复默认和脏表单离开确认。Profile 列表支持过滤、游标分页、新增、编辑和删除确认；编辑时稳定跨平台 ID 不可修改。颜色和名称模板提供即时安全预览，但预览不解释任意 BBCode、HTML 或脚本。

禁言管理展示跨平台身份、显示名、原因、永久或 UTC 截止时间和更新时间。创建、编辑和解除分别调用类型化 Mutation；创建后跨平台身份固定，解除必须再次确认目标。列表与表单的 loading、empty、stale、failed 和 forbidden 状态遵守本页实际状态机，不把协议异常或网络接受表示为禁言已生效。

完整字段、优先级、错误与恢复规则由[游戏聊天完整功能设计](superpowers/specs/2026-07-26-game-chat-design.md)定义。

### 审计与游戏事件

`/audit` 是 `Owner` 专用的只读工作台，页面内以两个标签分开统一审计与游戏事件。统一审计只呈现来源、操作者、目标、动作、状态和受控摘要，不在当前表格复制专用审计的敏感详情；游戏事件只呈现固定类型、主体、目标、发生时间和采集时间。

两个标签各自维护筛选、游标页码和请求状态。刷新当前标签只刷新对应数据；没有匹配记录时显示 Empty，有旧页的刷新失败显示 Stale，没有旧页的失败显示 Failed。统一审计的来源 gap 与游戏事件的 `QueueFull`、`StoreFailure`、`DrainTimeout` gap 使用独立警告区呈现，不占用正常记录行，也不被解释为玩家行为。

该审计与事件页面落实 `CAP-02`、`CAP-05` 和 `NFR-02` 的只读查询与状态边界；真实浏览器响应式与双语验收仍按[测试策略](test.md#证据基础第一波当前实现证据)保留，不能从组件测试推导 `NFR-03` 已完成。

#### 玩家坐标地图

1. `Owner` 从玩家二级导航进入 `/players/map`。页面使用 OpenLayers 和固定朝北的有限游戏 X/Z 坐标投影；地图工具栏显示当前鼠标坐标、最后选择坐标、缩放和图层入口，不提供旋转。
2. 第一阶段默认显示固定本地背景图、坐标网格、当前在线玩家标记和游戏日时。背景图不表示当前世界地形；玩家和游戏时间分别携带自己的 `observedAtUtc`，在线数据不可用时历史查询仍可独立使用。
3. 用户选择一名历史玩家和时间范围后加载分段轨迹。轨迹显示本次返回观察数，起点和终点使用可区分标记，首次加载自动定位到轨迹范围；时间控件、地图点和同步文本列表共享同一观察，切换筛选取消旧请求并将玩家、时间和观察定位保存在 URL。
4. 轨迹在内部连续性边界处自然断开，普通用户不看到 `gap`、原因或丢失数量。页面统一提示“轨迹由已保留的位置观察组成，不代表持续在线或实际移动路线”。
5. 图层面板可按需启用认证瓦片、region、历史玩家最后位置、商人、领地、载具和无人机。图层默认关闭，可见时加载，隐藏或页面不可见时暂停；成功加载后显示对象数量。历史最后位置不称为当前离线或当前位置；商人显示营业状态。没有可信生产瓦片根或真实游戏字段投影时，对应图层明确显示不可用，固定背景和其他成功图层保持可用。
6. 密集对象聚合，tooltip 显示摘要，popup 只读展示可用字段和观察时间。在线/历史玩家、领地、载具和无人机在规范身份可用时提供玩家资料跳转；当前阶段不读取玩家背包或载具具体储物内容。
7. 瓦片显示经确认的素材署名。工具栏“重新加载瓦片”只刷新浏览器 tile source；瓦片关闭、加载中或失败时继续显示固定本地背景图，不与服务端瓦片资源刷新/渲染作业混用。
8. 第三阶段提供矩形或圆形区域选择和时间范围，结果列表展示命中玩家、首次/最后命中、命中观察数和最后坐标，并可跳转历史详情或载入轨迹。动物和敌对实体只在满足缩放与范围限制时加载。
9. 在线、游戏时间、历史、瓦片和各业务图层分别表达 loading、ready、empty、stale、forbidden 和 failed；一个图层失败不清空其他成功图层。键盘和 320 CSS 像素窄屏通过同步列表完成等价选择。
10. 第 1 至第 3 阶段没有删除、传送、渲染或其他状态变更入口。小地图、玩家/载具背包、玩家专属监控区域、多玩家轨迹、热力图和 `minDistance` 不在本阶段范围。

该流程覆盖 `CAP-02`、`NFR-02` 和 `NFR-03`。详细图层、字段和加载边界见[玩家坐标地图设计规格](superpowers/specs/2026-07-26-player-coordinate-map-design.md)。

#### 地图管理操作（独立后续目标）

1. 领地删除、玩家传送和地图渲染从独立操作面板或确认对话框发起，不混入只读 popup；只有 `Owner` 可见和调用。
2. 传送采用“选择在线玩家—选择地图点或输入坐标—核对固定摘要—确认”的流程，不使用拖拽松手即提交。Stale、Offline 或身份变化时不能提交。
3. 删除领地固定显示所有者、坐标和领地标识；服务端瓦片资源刷新或渲染固定显示世界、范围和负载影响。完整地图渲染使用更强确认。
4. 提交后显示排队、运行、成功、失败、取消或结果未知。刷新页面后通过操作 ID 恢复权威状态；HTTP 成功不直接显示最终成功。
5. 操作成功只刷新相关图层或地图资源版本；失败保留当前地图、筛选和上一份已验证瓦片。

该流程覆盖 `CAP-02`、`CAP-05` 和 `NFR-02`，详细边界见[地图管理操作设计规格](superpowers/specs/2026-07-26-map-management-actions-design.md)。

### 日志排查

1. `Owner` 或 `Admin` 进入页面后，应用先订阅现有认证实时连接，再读取服务端内存中的最近原始日志；两路数据按统一 `sequence` 合并、排序和去重。`Viewer` 不显示导航入口，直接访问进入权限拒绝页。
2. 页面采用无卡片的全高工作台：顶部紧凑区域展示连接状态、缺口、当前缓冲数量和“清空页面”；中间日志区域占满剩余空间；底部命令输入始终可见。
3. 日志按普通文本节点和等宽字体逐字展示 `formattedMessage`；缺失时回退到 `message`，存在 `trace` 时按原字符串追加后续行。页面不拆分时间或级别，不提供搜索、筛选、匹配跳转、关联识别或日志行操作。
4. 页面位于底部时自动跟随最新日志。用户滚动离开底部后自动暂停跟随、保持阅读位置并累计“新增 N 条”；选择“回到最新”后滚动到底部、清零计数并恢复跟随。
5. 浏览器初始读取最新 1000 条，页面最多保留 2000 条；超过上限时从顶部淘汰。顶部区域显示当前缓冲数量，不把容量淘汰描述为服务端缺口。
6. “清空页面”只清除当前浏览器数组，不删除服务端内存日志、审计或实时游标；清空后新日志继续追加，断线重连不恢复本次已经清除的旧页面记录。
7. 快照失败但实时连接可用时，状态栏说明历史上下文不可用并继续显示新日志；实时连接中断时保留已有日志和最后接收时间并自动重连；收到 `gap` 时在状态栏明确标记不连续，不向原始日志区插入面板消息。
8. 输入第一个命令词时，页面按当前进程返回的命令名和别名前缀展示建议；方向键选择、Tab 补全、Esc 关闭，建议项显示名称、别名、说明、帮助和有效权限等级。目录不可用时自由输入与提交仍可用。
9. Enter 直接提交命令，不按命令名弹出确认。当前页面会话保留最近 50 条成功提交命令，连续重复原文不重复追加，可用上下方向键恢复并返回未提交草稿；历史不进入浏览器持久存储。
10. 提交成功后清空输入并等待原生控制台日志从实时流到达；请求返回的独立输出不渲染。失败或结果未知时保留输入并显示短暂通知，不向日志区插入命令行、结果或系统消息。

该流程覆盖 `CAP-02` 和 `NFR-02`。

### 公告与自动化

1. 即时公告先展示内容预览和目标服务器；首版目标固定为当前服务器。
2. 用户提交后看到排队、已发送、失败或结果未知，不允许因 HTTP 请求成功就显示游戏内已发送。
3. 创建定时任务时选择固定触发类型，填写内容与时间规则，并在保存前显示下一次预计触发时间。
4. 任务列表直接提供启停控制；编辑触发条件与删除任务需要确认，且展示最近执行结果和下次计划时间。
5. 同一触发重复到达时，界面只呈现一次权威执行记录，并允许通过审计查看去重结果。

该流程覆盖 `CAP-04`、`CAP-05` 和 `NFR-02`。

### 备份与跨重启恢复

1. 备份页将世界、Panel 数据库和服务器配置三个计划作为独立表单展示；每个表单保存服务端行版本。`409` 冲突时保留本地草稿、标记数据过期并要求刷新后核对，`400` 显示可读输入错误；手动备份提交后进入持续可追踪的任务状态。
2. 备份列表区分校验通过、校验失败、处理中和不可用；只有校验通过的备份可发起恢复。
3. 恢复确认页展示备份时间、大小、校验状态，以及“服务器将安全停止且必须重启”的明确影响。
4. Owner 完成强确认后，页面依次显示校验、待恢复已记录、正在关服和等待重启；服务器离线不等于恢复成功。
5. 服务端重启且面板恢复后，页面读取持久化结果，显示恢复成功、恢复失败或已回滚，并提供审计与备份详情入口。

恢复等待页允许关闭浏览器，重新打开后仍能从持久状态继续查看。该流程覆盖 `CAP-03`、`CAP-05` 和 `NFR-02`。

### 旧版本能力的纵向交付

1. 每个切片先从旧版固定提交中提取用户入口、字段来源、单位、空值、权限、失败和副作用证据，再由 7DPanel 定义独立页面与 API 合同。
2. 先交付能被一个真实页面消费的最小闭环；例如游戏资源目录先提供后端采集、查询、图标安全读取和 Admin 搜索，再由背包、奖励包、商店和自动化后续复用。
3. 依赖能力未实现时不显示伪入口，也不使用自由文本控制台命令临时替代；后续切片接入时再扩充类型化选择器和关联导航。
4. 切片上线后，页面只声明 7DPanel 已验证的行为；旧版存在但未确认安全或无法在当前游戏版本证明的行为保持未交付，并在目标蓝图记录处置。

该流程覆盖 `CAP-08` 至 `CAP-12`，并落实 `NFR-02` 的状态诚实要求。

## 状态与交互

### 通用状态规则

| 状态 | 展示与交互规则 |
|---|---|
| Loading | 首次加载使用与最终布局尺寸一致的骨架；局部刷新保留旧数据及原时间戳，避免整页闪空。 |
| Empty | 说明当前没有什么，并提供当前角色可执行的单一下一步；空列表不显示为加载失败。 |
| Success | 在动作位置显示持久结果，并可辅以短暂通知；涉及任务的成功必须能在任务或审计记录中再次找到。 |
| Partial | 综合结果中至少一个分区不可用或无权读取；其余已授权分区保持可见，并显示各自时间和受影响原因。 |
| Failed | 显示可理解的原因、发生时间、审计关联标识和适用的重试入口；保留用户可安全复用的输入。 |
| Offline | 全局状态条和受影响区域同时标记不可用；禁用依赖游戏状态的写操作，但允许查看本地历史、配置和审计。 |
| Stale | 仅表示刷新请求失败但仍有上一成功结果；继续展示该结果并明确提示“刷新失败，显示上次结果”。玩家 observation 的年龄是独立行级提示，不改变请求状态。 |
| RestartScriptStarted | 只表示已启动预配置的重启脚本，不表示脚本完成、服务器进程重启或健康检查成功；提示连接可能中断。 |
| Unknown | 表示请求可能已经开始但结果未确认；禁止直接重试可能造成重复副作用的动作，先提供刷新或查审计入口。 |
| Draining | 持续提示服务器正在关闭；禁用新写操作，保留正在收尾任务的状态与重启说明。 |
| Forbidden | 说明当前角色无权执行或查看，不泄露目标资源细节；提供返回有权页面的入口。 |
| Session expired | 中止新的提交并要求重新登录；不自动重放任何状态变更请求。 |

### 操作反馈与并发

- 按钮提交后保持固定尺寸，使用进度指示替换图标但不改变布局；同一幂等操作完成前不能重复提交。
- 列表更新不改变用户当前筛选、排序和滚动上下文；目标离线或记录变化时，在原位置说明变化而不是静默消失。
- 长任务不使用阻塞整页的模态框。模态框只用于提交前确认，提交后转为页面内任务状态。
- 危险确认必须包含目标和后果；恢复与封禁不得只依赖按钮颜色表达风险。
- 表格批量操作不进入首版，避免在权限、审计和结果语义未明确前扩大误操作范围。

### 语言切换与内容边界

- 首版支持简体中文 `zh-CN` 和英文 `en`；语言偏好只作为非敏感浏览器设置持久化，不跟随账号跨浏览器同步。
- 切换语言时，产品文案、导航、Nuxt UI 组件内置文案、Valibot 内置校验错误、日期与数字格式以及由稳定服务端错误码映射的用户消息必须同步更新。
- 切换语言保留当前路由、查询筛选和非敏感的未提交输入；密码、Bearer Token 和危险操作确认状态仍按安全生命周期清理，不因语言偏好持久化。
- 业务文案和服务端错误不得依赖翻译原始后端消息；前端根据稳定错误码选择当前语言消息，并保留 Correlation ID 或 Audit ID 供排查。
- Steam ID、玩家名、服务器名、IP、坐标、路径、控制台与日志原文、审计标识、API/协议标识和用户输入不翻译；其周围标签和辅助说明需要翻译。
- 缺少当前语言文案时回退到 `en`，不得显示翻译键、空白标签或把技术异常原文直接暴露给用户；缺失键必须可被测试发现。

### 权限表现

| 角色 | 界面能力 |
|---|---|
| `Owner` | 使用全部首版功能；管理用户和角色；发起恢复及其他 Owner 专属高风险操作。 |
| `Admin` | 查看运行、玩家、访问名单和模组信息，维护黑白名单并执行获准的玩家管理、公告、自动化和备份操作；不能查看服务器配置、管理任一权限体系、切换模组状态、管理 Owner 或发起恢复。 |
| `Viewer` | 只读查看被授权的状态、访问名单、模组、任务结果和审计；不能访问“控制台与日志”、最近日志、实时 `console-log`、动态命令目录或服务器配置，不显示状态变更入口。 |

`Viewer` 只属于管理面板，不作为未来玩家登录角色。未来玩家网页门户与玩家网页商城若立项，应提供独立的 `Player` 身份、导航和授权范围，不让玩家进入管理界面；`CAP-09` 的游戏内商店不要求该门户。

服务器治理逐动作权限矩阵由[服务器治理功能设计规格](superpowers/specs/2026-07-26-server-governance-design.md)定义；其他尚未实现动作仍需在对应设计中确认。前端隐藏不是授权边界，服务端拒绝仍必须有一致的页面状态。

### 响应式行为

- 桌面宽度优先支持长时间值守、表格扫描和日志排查；主要内容不以装饰性卡片分割成碎片。
- 窄屏保留概览、玩家单项处置、即时公告、任务状态和恢复结果查看，表格转换为字段明确的行详情，不依赖横向拖动完成关键操作。
- 日志在窄屏使用独立全宽区域，顶部只保留连接状态、缺口与清空操作，底部命令输入固定可达；命令建议从输入框上方展开，“新增 N 条”和“回到最新”不得遮挡输入。
- 任何固定工具栏、对话框和操作按钮都必须在 320 CSS 像素宽度下保持可访问，并容纳英文相对中文的文本扩展；文本不得截断到无法辨认目标或后果。

## 设计系统

### 视觉语言

- 定位为安静、克制、工作导向的运维界面。使用中性浅色或深色表面承载高密度信息，以绿色、琥珀色、红色和蓝色分别表达成功、警告、危险和进行中；不让单一色相支配整个产品。
- 服务器名称、页面标题和关键异常建立清晰层级，但面板内不使用营销式大标题、渐变背景、装饰光斑或层层嵌套卡片。
- 以未装饰的页面分区、数据表格、状态条和工具栏为主；卡片只用于真正独立的重复对象或需要边界的任务详情。
- 圆角克制且不超过 8px；边框、底色和留白共同表达层级，不依赖阴影堆叠。

### 字体、密度与布局

- 正文与控件使用清晰的无衬线字体；日志、Steam ID、IP、坐标、时间和审计标识使用等宽数字表现，确保对齐和复制准确。
- 字号不随视口宽度缩放，字距为 0；页面标题、分区标题、表格和辅助文字采用稳定层级。
- 桌面页面使用受约束的内容宽度与固定导航，数据表格可占满工作区；操作列、状态列和时间列保持稳定宽度，动态内容不能推动布局跳动。
- 默认密度适合重复运维，交互目标仍保持足够尺寸；可读性优先于在单屏塞入所有字段。

### 控件与图标

- 搜索用输入框，状态和角色用筛选菜单，模式切换用分段控件，启停任务用开关，时间与数值使用对应输入控件。
- 熟悉动作优先使用标准图标，例如刷新、暂停、播放、筛选、下载和更多菜单；只有语义不够明确时使用图标加文字，并为非显然图标提供工具提示。
- 主操作使用具体动词，如“发送公告”“创建备份”“确认恢复”；取消保持次要，破坏性操作不能与安全操作视觉等权。
- 状态不能只靠颜色表达，同时使用图标、文本标签和必要的时间信息。

### 可访问性

- 正文、控件、边框和状态颜色达到 WCAG 2.2 AA 对比度；键盘可以到达全部交互控件，焦点样式始终可见。
- 表格具备列标题和可理解的排序状态；实时日志与任务更新不能频繁打断屏幕阅读器，重要完成或失败使用克制的状态通知。
- 对话框打开后管理焦点，关闭后返回触发控件；错误信息与具体字段关联，并提供文本说明。
- 动画仅用于状态转换与进度，不作为理解结果的必要条件，并遵循用户减少动态效果的系统偏好。

### 待确认设计项

- 品牌标识、最终配色与字体资产尚未定义；不得阻塞以语义色和系统字体完成首轮可用性原型。
- `Admin` 的逐玩家动作权限和敏感玩家字段范围尚待确认；动态控制台已确认向 `Owner` 和 `Admin` 开放全部已注册命令，不按命令名称维护前端白名单或确认规则。请求拒绝与结果未知只在日志外反馈，审计可能不完整状态仍必须在产品的可见告警位置表达。
- 首版公开支持的最小浏览器和最小屏幕范围尚未成为产品合同；测试策略暂以 Chromium 稳定版和 320 CSS 像素作为设计验证基线。
