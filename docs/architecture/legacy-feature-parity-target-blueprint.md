# 旧版本功能对齐目标蓝图

> 本文记录 7DPanel 对齐旧版 `7dtd-serveradmin` 的目标边界、证据方法和底层优先顺序，不是当前实现证据。当前系统事实以[系统架构](../architecture.md)为准，产品能力以 [PRD](../PRD.md) 为准，页面体验以[产品设计](../design.md)为准，验证范围以[测试策略](../test.md)为准。

## 目标与基线

目标是用 7DPanel 当前的进程内 Mod、显式架构、Header Bearer、类型化游戏端口、专用审计和 Nuxt UI 管理面板，尽快覆盖旧版已经提供的主要用户可见与运营者可见能力。功能对齐按用户结果、输入约束、字段语义、副作用和失败行为判断，不要求旧路由、DTO、数据库、页面布局或内部类型兼容。

本轮分析固定以下 Git 提交作为可复查证据：

| 项目 | 固定提交 | 用途 |
|---|---|---|
| 当前 7DPanel | `ad58dcc` | 功能对齐启动前的当前实现基线；后续状态以新提交和当前架构文档更新为准 |
| 旧版 backend | `277996d` | Controller、模块、实体、migration、游戏适配和字段提取的可执行规格 |
| 旧版 frontend | `60fc816` | 页面入口、字段展示、管理流程和操作者可见状态的可执行规格 |

旧仓库后续提交不会自动改变本蓝图。只有显式重新盘点并更新固定提交后，才能成为新的对齐证据。

## 对齐原则

1. **行为证据，不是代码来源。** 可以运行旧项目、观察页面/API/数据库结果、定位字段来源和比较边界，但不得复制其源代码、批量改写命名后移植，或把旧程序集作为新运行时依赖。
2. **当前合同优先。** 旧版能力若与当前权限、线程、审计、路径安全、状态诚实或恢复规则冲突，保留用户结果并采用当前更安全的行为；差异写入规格和验收。
3. **纵向切片交付。** 每次同时提供一个真实后端来源、Application 用例、Web 合同、Admin 页面和适用验证。不得先建立没有非测试消费者的通用 repository、事件总线、handler registry 或模块框架。
4. **类型化副作用。** 旧版能通过控制台命令完成某项操作，不代表新 Web API 可以接受命令原文。高风险操作逐项定义目标、参数、权限、线程、审计、超时和未知结果。
5. **当前事实与目标分离。** 实现和验证完成后才把事实提升到 `docs/architecture.md`；本蓝图中的阶段、目录和候选职责不能用于宣称功能已经存在。

## 行为与字段提取方法

每项切片在设计前建立一张最小证据表，至少记录：

| 字段 | 必须回答的问题 |
|---|---|
| 用户入口 | 旧版从哪个页面、API、游戏命令或事件触发，用户最终得到什么结果 |
| 稳定身份 | 玩家、世界、物品、作业或外部主体以什么键关联，重连和重启后是否稳定 |
| 原始来源 | 字段来自 7DTD 活对象、配置、日志、文件、旧数据库还是计算结果 |
| 时间与线程 | 何时观察，是否必须在游戏主线程复制，是否允许缓存，采样时间是什么 |
| 类型与单位 | 数值范围、坐标顺序、时间单位、枚举、格式化和精度 |
| 空值与版本 | 缺失、未加载、不适用、未知和旧游戏版本分别如何表达 |
| 失败与副作用 | 失败前后发生了什么，能否重试，是否可能结果未知，是否需要补偿 |
| 权限与敏感性 | 哪个角色或玩家可见/可用，哪些字段不能返回、记录或导出 |

旧版代码只用于找到候选入口和来源；最终映射必须再用当前 `7dtd-reference/`、目标 7DTD 版本或受控运行观察确认。游戏活对象只能在获准线程读取并复制为产品自有不可变值，不得进入 HTTP、后台 writer 或前端合同。旧版把缺失值显示为 `0`、空字符串或成功时，7DPanel 仍使用当前的未知、部分可用和结果未知语义。

## 数据、审计与缺口

新运行时使用自己的 migration 和能力范围 Store，不直接读取旧数据库。若将来需要导入旧数据，单独提供可移除、可重复运行、带 dry-run 和导入报告的离线 importer；导入器不成为正常启动依赖，失败不能修改旧数据库，映射冲突必须显式报告。

审计与事件按以下边界演进：

| 数据 | 权威用途 | 与统一查询的关系 |
|---|---|---|
| 玩家动作、控制台命令、聊天、服务器操作及后续经济/作业专用记录 | 保存各自意图、状态机、结果和恢复语义 | 统一审计只读投影引用专用记录，不覆盖或改写它们 |
| 游戏事件 | 保存玩家加入、离开、击杀、死亡等已观察事实 | 可在统一页面关联查询，但来源保持为游戏事件 |
| `gap` | 表示异步观察在队满、持久化失败或关服排空时可能缺失的时间/序列范围 | `gap` 不是一条玩家行为或管理员动作，不能被投影为已发生事件，也不能证明数据一定丢失 |

能够在副作用前持久化的高风险动作继续采用 fail-closed 审计意图；旁路观察、聊天历史和游戏事件采用不阻断游戏的 fail-open writer，并通过可见 `gap` 表达证据连续性风险。两类语义不得混用。

## 底层优先开发顺序

### 阶段 0：冻结合同与旧版证据

- 以本蓝图、PRD 和已批准 Change Record 固定能力处置；
- 每个切片开始时只读取相关旧模块，不做一次性全量重构；
- 把待实现能力拆成可以独立演示和回滚的纵向切片。

### 阶段 1：游戏资源目录

采用状态：已于 2026-07-26 按[设计规格](../superpowers/specs/2026-07-26-legacy-parity-game-resource-catalog-design.md)和[实施计划](../superpowers/plans/2026-07-26-legacy-parity-game-resource-catalog.md)完成第一项纵向切片；当前实现事实见[系统架构](../architecture.md#游戏资源目录切片)，验证证据见[测试策略](../test.md#游戏资源目录当前实现证据)。

- 已从当前游戏版本边界复制物品、方块、可见性、堆叠/品质、本地化名称和 PNG 图标元数据；
- 已提供版本化不可变 snapshot、安全图标读取、搜索/分页 API 和 Admin 响应式只读页面；
- 后续第三至第五波已经消费该类型化目录完成玩家物品动作、奖励包、商店和固定自动化动作；当前实现事实见[系统架构](../architecture.md#六波次功能对齐当前代码状态)，真实游戏证据缺口见[测试策略](../test.md#六波次功能对齐当前工作树证据)。

这是第一项实施切片。它只读、可缓存、不会修改玩家或世界，同时能尽早验证旧版字段提取、游戏线程复制、路径安全、OpenAPI 生成和 Admin Feature 的完整链路。

### 阶段 2：运行指标与证据底座

- 补齐旧版仪表盘游戏指标及其采样/不可用语义；
- 增加游戏事件 Store、专用记录索引和统一只读审计投影；
- 建立后续作业、经济和自动化需要的稳定关联 ID，不建立通用事件总线。

### 阶段 3：玩家与世界只读模型

- 玩家 Profile、会话、活动、位置、背包、技能和每日摘要；
- 背包快照比较、物品来源证据与补偿记录；
- 领地、车辆、无人机容器和地图业务图层的只读查询。

### 阶段 4：作业、调度与备份

- 先交付一个真实持久作业消费者，再抽取必要的作业状态共性；
- 世界、数据库和配置备份及保留、下载、删除；
- Cron、计划命令、计划重启、公告和可恢复运行记录。

### 阶段 5：类型化动作与游戏内命令

- 禁言、发放/删除物品、玩家重置、家/城市/好友/返回点传送；
- 登记式游戏命令目录和私聊结果；
- 投票踢人、投票重启及类型化结果，不开放任意命令脚本。

### 阶段 6：经济、商店与奖励

- 原子经济账本、冻结、调整、转账、交易和排行榜；
- 奖励包、商店、库存、兑换码、在线奖励和成就；
- 幂等发放、可恢复中间状态和管理员补偿。

### 阶段 7：事件自动化与外部集成

- 玩家加入、离开、聊天和 Cron 触发的固定规则、条件、动作、dry-run 与冷却；
- Discord 出站/入站、账号绑定和远程 allow-list；
- GeoIP 策略、缓存、失败模式和诊断；
- 功能模块启停只在已有真实模块消费者后统一展示。

### 阶段 8：高风险世界工具

- 按使用价值逐项实现区域复制/填充、方块、Prefab、实体、撤销、reload 和 GC 等工具；
- 每项独立定义参数白名单、主线程或后台作业边界、强确认、审计和恢复能力；
- 无法证明结果或恢复语义的旧版工具可以延期，不用通用控制台页面冒充功能对齐。

阶段按底层依赖排序，但不要求一个阶段的所有低价值边角完成后才能开始下一个阶段。允许在依赖已稳定时交错实施，前提是每个合并单元仍是完整纵向切片，且没有为未来阶段预建无消费者基础设施。

### 实施后的剩余目标

六波次的 migration、主要 Domain/Application/Adapter/Web/DI 和 Admin 页面已经在当前工作树形成代码切片，已采用结构不再由本 Target 文档重复定义。以下条目仍保留为目标或验收缺口：

- `daily/claim`、`shop`、`tpa/tpaccept/tpreject` 的专用持久合同、Community 全量查询、传送设置/投票配置 `expectedRowVersion` 和私人家覆盖 CAS 已提升为 Current；其他可变 Community 记录仍需在存在丢失更新风险时逐项补明确版本语义，不能用通用仓储抽象代替；
- Discord Gateway 网络连接和 interaction Ed25519 transport 已提升为 Current；仍缺真实 sandbox 往返，以及 GeoIP/MaxMind 真实加入决策；
- 奖励、成就和在线奖励 evidence runtime 已接入生产持久观察完成入口；真实奖励发放与补偿恢复仍需环境证据；
- 真实备份恢复、玩家动作、经济/传送/投票、世界 change set/undo 和危险世界工具必须在受控 `v3.0.1-b4` 实例取得证据；危险操作前必须确认备份与回滚目标；
- 最终 Admin typecheck、AppShell/router/i18n/Community、world-tools 和 player-map 聚焦测试及 JSON key audit 已按[测试策略](../test.md#六波次功能对齐当前工作树证据)取得代码侧证据；modules 完整聚焦、定向 lint、全量门禁、完整 Playwright 页面矩阵和 Linux 候选发布证据仍未闭合，当前精简实现不能替代这些边界。

连续实施固定占用 `008_EvidenceFoundation.sql`、`009_JobsBackupsSchedules.sql`、`010_PlayerEvidenceActions.sql`、`011_EconomyCommunity.sql`、`012_AutomationIntegrations.sql` 和 `013_WorldToolsAndFeatureModules.sql`。每个后续 migration 在保留专用权威记录的同时重新创建第一波只读 `unified_audit_projection`，只增加新波次稳定摘要；不得复制业务正文、Secret、路径或大字段，也不得把 gap 投影为已发生动作。

上述六份规格已于 2026-07-26 一次性批准，每份规格已经创建且只创建一个主实施计划。执行按波次顺序连续推进；波次内部可以并发实施 Application/Domain、Adapters、Web/OpenAPI、Admin 和聚焦验证，但同一 migration、组合根、生成合同和 Current 文档由主执行者串行合流。只有产品决策变化、破坏性真实环境操作或真实环境证据阻塞才暂停请求用户确认。
