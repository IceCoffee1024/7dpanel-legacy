# 游戏聊天完整功能实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为 `Owner` 一次性交付实时聊天、历史聊天、聊天设置和彩色聊天，并保持游戏主线程、权限、持久化和纯文本安全边界可靠。

**Architecture:** SevenDays Adapter 使用一个 `ModEvents.ChatMessage` 协调器复制原始事件、决定彩色替换并生成唯一 canonical 消息；现有事件窗口负责当前进程实时上下文和 SSE，专用有界 writer 尽力写入 SQLite 历史。Web 通过 Owner-only REST/OpenAPI 暴露查询、发送、设置和 Profile，Admin 复用唯一应用级 SSE、生成客户端和页面局部状态组成四项聊天页面。

**Tech Stack:** .NET Framework 4.8、C# 11、7DTD `v3.0.1-b4` Mod API、Microsoft DI、Channels、Dapper、DbUp、Microsoft.Data.Sqlite、OWIN/Web API、NSwag、Vue 3、TypeScript、Vite、Nuxt UI、VueUse、Valibot、Vue I18n、Hey API、Pinia Colada、Vitest、Playwright。

---

## 主规格

本计划只实现已确认的[游戏聊天完整功能设计](../specs/2026-07-26-game-chat-design.md)，追踪 `CAP-06`、`CAP-05`、`NFR-02`、`NFR-03` 和 `NFR-04`。计划不得新增禁言、敏感词、Discord、跨服聊天、玩家门户、全文搜索、导出或通用聊天命令框架。

## 实施约束

- 不安装 NuGet 或 pnpm 包，不创建第二条 SSE、聊天 Pinia Store、通用 Event Bus、Feature 注册表或没有生产消费者的抽象。
- `SChatMessageData`、`EChatType`、`ClientInfo` 和游戏活对象只存在于 SevenDays Adapter；Application、Persistence 和 Web 只接触不可变产品类型。
- 游戏聊天回调不得访问 SQLite、网络或请求 scope，不得等待后台写入，也不得为每条消息创建 `Task.Run`。
- 彩色和非彩色消息由同一协调器处理。成功替换后只广播一次并阻止原版；命令、空消息、未知上下文和任何异常都 fail-open。
- 实时最近消息读取现有当前进程事件窗口，历史查询读取 SQLite；两者不得伪装成同一跨进程连续序列。
- Admin 所有 Query 沿用全局 `staleTime: 0`、`refetchOnWindowFocus: false`；消息窗口、草稿、滚动和发送历史不持久化。
- 受控 OpenAPI 快照及 `frontend/apps/admin/src/shared/api/generated/` 只通过现有生成命令更新，禁止手改。
- 每个任务只运行列出的聚焦检查；功能稳定后只运行一次聚合检查和一次真实 7DTD 人工聊天验收。

## 完成标准

- `Owner` 能访问四项聊天页面；Admin、Viewer 和未认证用户在导航、路由、REST 和 SSE 都不能取得聊天内容或修改聊天状态。
- 当前进程最近聊天和 `chat-message` 使用统一 sequence，无快照/live 重复；历史使用 SQLite keyset cursor，writer 失败形成 gap 且不阻塞游戏聊天。
- 全局和私聊通过类型化主线程发送器执行，目标、结果和长度可审计，正文不进入审计；失败保留前端输入且不自动重试。
- 聊天设置、彩色设置和 Profile 事务成功后立即替换运行时快照，失败继续使用旧值。
- 命令绕过彩色；普通消息按系统、管理员、Profile、频道优先级渲染；成功替换只广播一次，异常放行原版。
- 所有 Web 聊天内容使用纯文本，四个模板变量和颜色权限边界明确；不安装新包，不增加第二条 SSE 或通用聊天框架。
- 聚焦检查、一次聚合检查和一次真实 7DTD 人工聊天验收完成；文档只提升有实现和证据支持的当前事实。
