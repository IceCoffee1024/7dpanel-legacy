# 旧版本功能对齐第二波：持久作业、备份恢复与调度设计规格

## 上游、状态与波次职责

本规格落实[产品需求](../../PRD.md) `CAP-03`、`CAP-04`、`CAP-05`、`NFR-01`、`NFR-02`、`NFR-03`、`NFR-04` 与 `NFR-05`，遵循[后端目标架构蓝图](../../architecture/backend-target-blueprint.md)的作业、备份、恢复、公告和调度边界，以及[旧版本功能对齐目标蓝图](../../architecture/legacy-feature-parity-target-blueprint.md)的底层顺序。当前实现仍以[系统架构](../../architecture.md)为准。

这是六波次规格集的第二波。备份是持久作业的第一个真实消费者；只有备份、恢复、计划命令和公告表现出共同状态后才提取最小共性，不预建通用工作流平台。

## 用户结果

- `Owner` 可以手动或按计划创建世界、7DPanel 数据库和服务器配置备份，查看状态、下载、删除和保留结果。
- `Owner` 可以从已校验备份发起跨重启恢复，并在重新打开面板后继续查看最终状态。
- `Owner` 与 `Admin` 可以发送即时公告；只有 `Owner` 可以管理欢迎、轮播、血月公告、计划命令和计划重启。
- 所有长操作在刷新页面或进程重启后仍有可查询终态；排队、脚本启动或服务器离线不被表示为成功。

## 持久作业模型

首批作业类型是 `WorldBackup`、`PanelDatabaseBackup`、`ServerConfigurationBackup`、`Restore`、`ScheduledConsoleCommand`、`ScheduledRestart` 和 `ScheduledAnnouncement`。每种作业使用自己的类型化 payload；数据库只共享以下生命周期字段：

- 服务端生成的 `jobId`、作业类型、操作者、创建/开始/完成 UTC；
- `Queued`、`Running`、`PendingRestart`、`Succeeded`、`Failed`、`Cancelled`、`Interrupted`、`ResultUnknown`；
- 幂等键、进度摘要、稳定错误码和 correlation ID；
- 不保存 Bearer、浏览器路径、任意环境变量或原始异常。

作业在入队前持久化。单消费者有界队列拥有读取循环和并发槽，启动时把遗留 `Running` 变为 `Interrupted`，并按作业类型决定是否可安全恢复。取消只对未开始或明确支持取消的后台阶段生效；游戏或文件副作用开始后不能用 HTTP 取消覆盖真实结果。

备份/恢复状态转换是第一个足以建立 Domain 项目的真实不变量。`LSTY.SevenDPanel.Domain` 在本波只承载备份/恢复纯状态机和 Cron/并发策略；后续经济波次需要的类型到对应真实消费者出现时再增加。Domain 不引用 Application、Hosting、SQLite、文件或游戏程序集。

## 备份

### 类型与配置

世界、7DPanel 数据库和服务器配置各有独立启停、Cron、时区、目标保留数量、目标保留天数和压缩设置。服务器本地配置定义批准备份根及不透明 `backupRootId`；`Owner` 可以为每类备份选择批准根，但浏览器不能提交或读取目录路径。备份列表包含类型、世界标识、游戏版本、创建时间、大小、SHA-256、manifest 版本、校验状态和关联作业。

### 执行流程

世界备份在需要时先通过类型化 gateway 请求 7DTD 保存，并等待可确认的保存提交完成；无法确认时不继续发布可恢复归档。数据库备份使用 SQLite 官方一致性能力或已验证的受控副本流程；服务器配置只包含批准文件，不能把任意路径加入归档。

归档在服务端临时根创建，写入 manifest、逐项大小与哈希后压缩并重新读取校验。只有完整校验通过的临时归档才原子提升为目录项；失败输出清理或隔离，不出现在恢复候选列表。清理策略不能删除运行中、待恢复或被显式保留的备份。

下载按备份 ID 读取批准目录项，固定 attachment 文件名并禁止路径穿越。删除要求 `Owner` 明确确认，先验证没有运行中/待恢复引用，再删除目录项和文件；部分失败保留可修复状态。

## 跨重启恢复

恢复仅允许校验通过且类型匹配的备份。`Owner` 必须提交备份 ID 和服务器生成的确认值；服务端重新校验归档、类型、世界和当前冲突后，持久化 `PendingRestart` 作业与审计意图，原子写入待恢复 marker，再请求固定安全关服。

下一次 Mod 初始化在世界文件打开前读取 marker、重新校验归档并创建回滚副本，然后进入 `Applying`。成功后写入 `Succeeded`、清除 marker 并保留回滚摘要；失败时尝试回滚并写入 `Failed` 或 `RollbackFailed`。服务器停止或重新启动本身不表示恢复成功。

真实 `v3.0.1-b4` 无法证明“世界打开前”时机时，实施必须暂停该恢复路径并进行一次受控时序验证；不能把在线覆盖或未经验证的启动钩子作为替代。

## 公告、Cron 与计划命令

即时公告由 `Owner` 或 `Admin` 发布，内容为 `1..500` 个纯文本字符，经过类型化公告 gateway 在游戏线程发送并返回真实结果。欢迎、轮播、血月、计划命令和计划重启仅 `Owner` 管理。

调度条目包含服务端生成 ID、固定触发类型、五字段 Cron、`TimeZoneInfo` 时区 ID、启用状态、并发策略、下次触发、最近执行和类型化配置。并发策略固定为：

- `SkipIfRunning`：已有同计划作业运行时记录一次跳过结果；
- `QueueOne`：最多保留一个尚未开始的补充运行，不无限累积。

服务重启后对每个计划最多补偿一次错过触发，并把原计划时间作为幂等键的一部分。计划命令复用现有控制台 gateway，但配置保存和执行记录与网页即时命令分离；不得创建任意脚本或 shell 动作。计划重启只触发既有预配置脚本动作，不接收路径、参数或环境变量。

## 接口与 Admin

- `/api/v1/jobs`：按类型、状态、时间 keyset 查询和读取单项；只返回角色允许的作业。
- `/api/v1/backups`：配置、手动创建、列表、下载、删除和恢复。
- `/api/v1/schedules`：公告、命令和重启计划 CRUD、启停和最近运行。
- `/api/v1/announcements`：即时公告。

Admin 新增“备份与恢复”和“公告与调度”页面。备份页把计划、当前作业和备份目录分开；恢复确认持续显示类型、时间、大小、校验与必须重启。调度页显示时区、Cron 解释、下一次触发、并发策略和最近结果。所有 Mutation 不做乐观成功，202 只表示已接受并返回 `jobId`。

## 生命周期与背压

持久作业 consumer 和 scheduler 是两个明确生命周期组件：scheduler 只产生到期意图，不执行作业；consumer 读取已持久化工作。启动先迁移与恢复作业，再接收 HTTP/游戏触发；关闭先停止新生产，再完成队列并在截止时间内排空，未完成作业写入 `Interrupted` 或保持可恢复状态。

长时间世界备份不得占满所有短作业槽；备份和恢复互斥，配置/数据库备份可按已验证资源策略并行。队满时新请求返回容量不足，不创建无人消费的作业；持久化成功但入队失败的 `Queued` 作业由恢复扫描重新投递。

## 安全与失败语义

- 浏览器不提交路径、归档名、命令脚本、进程参数或环境变量。
- ZIP 读取拒绝绝对路径、`..`、重复规范目标、reparse 逃逸、超限条目和解压炸弹；大小、条目数和压缩比均有服务端上限。
- 磁盘空间不足、写入失败、哈希不匹配、文件占用、保存结果未知和关服失败使用不同稳定状态。
- 下载使用 Header Bearer、private cache 和 `nosniff`；错误不泄露文件系统布局。
- 备份、删除、恢复、计划变更、公告和计划执行均记录专用操作审计；Secret 和完整命令输出不进入摘要。

## 非目标

- 不支持浏览器指定任意目录、任意文件、任意 shell 或通用工作流 DAG。
- 不支持旧数据库在线迁移、多服务器调度、云对象存储或跨节点锁。
- 不把临时配置写入产生的 `.bak` 文件表示为产品备份。
- 不在本波实现事件自动化规则、经济、奖励、Discord 或世界编辑工具。

## 精简验证

- Domain 状态机、幂等键、Cron/时区、错过触发和并发策略单元测试。
- SQLite 作业恢复、重复触发、锁竞争、迁移幂等和查询测试。
- 临时文件系统中的三类备份、manifest/hash、原子发布、清理、下载/删除路径安全和损坏归档测试。
- OWIN 权限、确认值、202/job 查询、Problem Details 和 OpenAPI 生成测试。
- Admin 状态机、刷新恢复、确认、非乐观成功和双语聚焦测试。
- 只执行一次真实世界保存/备份和一次跨重启恢复演练；恢复会改变真实数据时必须使用受控测试世界和可回滚副本。

## 完成条件

- 三类备份、计划、目录管理和跨重启恢复具有可查询状态与适用真实证据。
- 即时公告、Cron、计划命令和计划重启具备持久运行记录、幂等与并发规则。
- 作业抽象只有本规格中的真实消费者，不接受任意 payload 或脚本。
- 排队、关服、重启、失败和结果未知在 API、Admin 与审计中保持一致且不伪造成功。
