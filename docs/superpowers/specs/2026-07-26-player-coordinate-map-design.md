# 玩家坐标地图设计规格

## 上游、目标与事实边界

本规格实现[产品需求](../../PRD.md) `CAP-02` 的只读玩家坐标地图，并遵循
[产品设计](../../design.md)的 Owner-only、状态诚实和可访问性要求。当前可复用事实见
[系统架构](../../architecture.md)：在线 `PlayerSnapshot` 已包含 `position`，历史位置已随
`player_history_snapshots` 持久化。本文描述的是第 1、2、3 阶段目标能力；代码和适用验证完成前，
不得把地图路由、图层或查询接口写成当前实现。

旧项目 `GPSMap` 仅作为功能盘点和 7DTD 字段来源线索。目标实现根据当前项目边界重新设计，
不复制旧代码，也不把旧项目行为当作当前游戏版本兼容证据。

## 总体决策

- 页面路由为 `/players/map`，位于在线玩家、历史玩家并列的玩家二级导航。
- 三个只读阶段统一采用 OpenLayers，不再建设一次性的 Feature SVG 地图。地图使用自定义游戏坐标投影，
  明确世界 extent、X/Z 轴方向和像素映射，不把游戏坐标伪装成经纬度。
- 地图默认只加载第 1 阶段的基础内容；后续图层默认关闭，仅在可见时请求，隐藏或页面不可见时暂停刷新。
- 地图固定朝北，不提供旋转；保留标准缩放和平移。可折叠小地图作为后续候选，不进入第 1 至第 3 阶段。
- 瓦片尚未启用、加载中或当前不可用时，地图显示随 Admin 静态资源发布的固定本地背景图，并叠加坐标网格和明确状态；背景图不能冒充当前世界地形，也不得复制旧项目素材。
- 在线位置复用现有在线投影；历史轨迹复用 `player_history_snapshots`；不增加第二张位置历史表、第二个历史
  Channel、Save 回调工作或 HTTP 请求时的游戏对象读取。
- 历史规范身份始终是 `crossplatformIdentity.combinedId`。没有该身份的 observation 不持久化，地图也不按
  名称、IP、实体 ID 或原生平台身份猜测合并。
- 用户界面和公开地图合同不出现 `gap`、缺失原因或丢失数量。后端根据已知历史缺口、身份边界和无效位置
  生成不带原因的 `segments`；前端只绘制段内连线，从视觉上自然断开。
- 地图统一提示：“轨迹由已保留的位置观察组成，不代表持续在线或实际移动路线。”单点段显示点但不画线。
- 历史轨迹标出起点和终点、显示本次返回观察数，并在首次加载时自动定位到轨迹范围；不提供旧版 `minDistance` 筛点，避免对已经执行保留策略的历史再次静默删点。
- 第 1 至第 3 阶段均只读。删除领地、传送玩家、服务端瓦片资源刷新或渲染等改变状态的能力由独立的
  [地图管理操作设计规格](2026-07-26-map-management-actions-design.md)拥有。

## 旧项目功能盘点与取舍

### 可借鉴的功能

旧 `GPSMap` 已覆盖以下能力，作为当前设计的需求证据：

- 自定义 `SDTD-CRS`、世界范围、栅格瓦片、缩放旋转、缩放条、小地图、图层切换和鼠标/点击坐标；
- 在线玩家、离线玩家最后位置、玩家历史轨迹、region 网格、领地、商人、载具、无人机、动物和敌对实体；
- 聚合点、点击聚合缩放、重叠点展开、tooltip、只读 popup，以及 URL 驱动的轨迹和区域选择；
- 页面激活后恢复、隐藏后暂停、图层可见时加载和不同图层的独立刷新；
- 矩形或圆形区域选择，并按时间范围反查曾进入区域的玩家。

旧后端还提供了可借鉴的字段提取线索：

| 图层 | 旧项目字段来源线索 | 当前方案约束 |
|---|---|---|
| 玩家身份 | `PersistentPlayerData.PrimaryId.CombinedString` | 使用当前已批准的 `crossplatformIdentity.combinedId` |
| 玩家轨迹 | Join、Leave、Save、Timer Sampler | 只复用当前 Save 历史快照，不增加周期扫描或独立采样表 |
| 领地 | `PersistentPlayerData.LPBlocks`、`World.IsLandProtectionValidForPlayer`、`LastLogin` | 在目标游戏版本验证后复制成不可变投影；`LastLogin` 不代表持续在线 |
| 商人 | world prefab/trader、区域和保护范围 | 由 SevenDays Adapter 复制为产品 DTO，不向 Web 暴露游戏对象 |
| 载具 | `VehicleManager.GetVehiclesECDList()`、已加载实体或持久 `EntityCreationData.pos` | 已加载与未加载统一映射为可空字段，无法提取时不以 `0` 冒充 |
| 无人机 | `DroneManager.GetDronesList()`、已加载实体或持久位置 | 同上，明确数据观察时间和加载状态 |
| 世界网格 | chunk 16、region 512、世界 extent | 必须在当前游戏版本和实际世界元数据中验证，不硬编码旧值为事实 |

### 明确不采纳的做法

- 不在请求、Timer 或后台线程直接遍历 `ConnectionManager`、`World`、Manager 或 Unity 活对象；
- 不在 Save/事件回调同步访问 SQLite，也不为每次 Save 创建 `Task.Run`；
- 不建立重复的位置历史，不按距离阈值静默丢点后仍绘制连续折线；
- 不把全部候选行读入内存再完成区域过滤，空间查询必须在数据库中有界执行；
- 不把离线最后位置解释为在线状态，不从 `lastLoginUtc` 推导两个时间点之间持续在线；
- 不在只读 popup 混入删除领地、拖拽传送或渲染作业入口；
- 不通过 `PlayerDataFile.Load` 为 HTTP 请求进行离线磁盘回源；
- 不使用 `0`、空字符串或默认枚举冒充无法提取的字段。

## 统一地图与数据边界

```text
SavePlayerData (game thread)
  -> existing immutable PlayerSnapshot
  -> existing online projection
  -> existing bounded history Channel -> player_history_snapshots

Approved map projections (game thread copy only)
  -> immutable trader / land claim / vehicle / drone / entity snapshots
  -> bounded in-memory latest projections with observedAtUtc

Owner /players/map
  -> map metadata + authenticated tiles
  -> independent bounded layer queries
  -> historical position query -> observations + internal continuity evidence
  -> Application builds public segments without gap details
  -> OpenLayers layers + synchronized accessible list/details
```

地图元数据至少包含 `worldName`、有限世界 extent、坐标轴约定、可用缩放级别、瓦片规格和当前地图资源版本。
前端只能根据元数据建立 projection、tile grid 和视图范围，不能从名称或默认世界大小猜测。

地图另读取游戏时间不可变快照，显示游戏日数、小时、分钟、`observedAtUtc` 和可用状态，默认每 30 秒刷新；
失败时保留上一成功值并标记 Stale，不直接从 `World` 或浏览器时钟推算。

所有依赖 7DTD/Unity 活对象的数据先在游戏线程复制成不可变产品 DTO，再交给线程安全投影。HTTP 只读取投影；
单个慢客户端、瓦片读取或 SQLite 查询不能阻塞游戏线程。图层分别返回自己的 `observedAtUtc` 和可用状态，
不能因为某一图层失败就清空其他成功图层。

## 第一阶段：地图基础、在线位置与历史轨迹

### 后端合同

- 增加 Owner-only 地图元数据查询；未取得真实世界元数据时返回明确不可用，不生成虚假 extent。
- 在线玩家继续使用现有 31 字段投影及各自 `observedAtUtc`。
- 历史位置查询输入为非空 `crossplatformIdentity.combinedId`、`fromUtc`、`toUtc`；范围最长 30 天，原始观察
  最多 5000 条。越界返回明确错误，不静默截断。
- Store 按 `(crossplatform_id, observed_utc, snapshot_id)` 稳定读取已有 `position_x/y/z`。Application 根据内部
  历史缺口、身份不一致、非有限坐标或顺序异常构建 `segments`；公开地图响应不返回缺口原因和数量。
- 每个轨迹点保留 `snapshotId`、名称、X/Y/Z 和 `observedAtUtc`，从而让地图点、时间定位和快照详情引用同一次
  observation。历史查询不依赖游戏 ready。

### 前端交互

- 进入页面后并行加载地图元数据、在线玩家和历史玩家摘要；未选择历史玩家时只显示在线标记和选择提示。
- 使用 OpenLayers 自定义 projection、有限 extent、坐标网格、缩放/平移、鼠标坐标和最后选择坐标。
- 地图顶部显示游戏时间；不可用时显示自己的加载、Stale 或不可用状态，不影响玩家和历史轨迹。
- 选择一个历史玩家及时间范围后加载 `segments`。切换筛选会取消旧请求，旧响应不能覆盖新选择；玩家、时间和
  选中观察写入 URL，刷新后可恢复。
- 时间控件只定位到已返回观察；地图点、时间控件和同步文本列表共享同一选中 `snapshotId`。
- 轨迹使用可区分的起点/终点标记并显示本次返回观察数，首次成功加载后自动 fit；用户随后手动移动地图时不反复抢回视口。
- 在线标记和历史轨迹状态独立表达。在线查询失败时，已成功取得的历史轨迹仍可查看。
- 页面区分 loading、ready、empty、partial、stale、forbidden 和 failed。刷新失败可保留最后已验证数据，但必须
  显示原观察时间与 Stale 状态。
- 键盘和窄屏用户可通过同步文本列表完成玩家、时间与观察选择，不要求精确地图拖拽。

## 第二阶段：认证瓦片与低频业务图层

### 图层范围

- Header Bearer 认证的真实世界栅格瓦片；Token 不进入 URL、日志、缓存键或静态 HTML；
- 根据元数据在前端生成的 region 网格与 `r.x.z.7rg` 标签；
- 历史玩家最后保留位置；该图层不宣称玩家当前离线或仍位于该处，显示 `observedAtUtc` 并排除当前在线投影中同一规范身份的玩家；在线投影不可用时不作离线判断；
- 商人位置、prefab/区域、保护范围和营业/关闭状态；
- 领地石位置、范围、规范所有者身份、有效状态和可用的最近登录时间；
- 载具位置、类型、规范所有者、加载状态，以及可空的燃油、品质、锁定和储物数量；
- 无人机位置、规范所有者和加载状态。
- 玩家、领地、载具和无人机在规范所有者身份可用时提供玩家资料跳转；在线玩家跳转当前详情，历史玩家或所有者跳转历史详情。跳转不改变地图筛选。

### 加载与呈现规则

- 每个图层拥有独立 query、状态、缓存和刷新周期；默认关闭，可见时才加载，隐藏或页面不可见时暂停。
- 静态/低频图层按地图资源版本或较长周期刷新；载具、无人机等动态图层使用较短但有下限的周期。请求采用
  single-flight、取消和结果上限，不建立全图高频轮询。
- 瓦片由同源受保护端点读取。前端 tile loader 使用当前 Authorization Header 获取 Blob 并管理对象 URL 生命周期；
  服务端只接受合法世界、zoom、x、y，不接受浏览器提供的文件路径。
- 地图提供“重新加载瓦片”只读按钮，只清理/刷新当前浏览器 OpenLayers tile source，不创建服务端作业；它与地图管理规格中的服务端瓦片资源重建是两个不同动作。
- 瓦片显示经确认的本地化署名，至少保留 `© The Fun Pimps LLC`；最终文本在实现时依据游戏素材授权复核。瓦片加载前、加载失败或图层关闭时继续显示固定本地背景图。
- 密集点使用 OpenLayers 聚合；点击聚合可缩放或展开重叠点。tooltip 只显示摘要，popup 显示只读详情；字段未知
  时显示未知，不显示伪造的零值。
- 图层面板在成功加载后显示当前返回对象数量；失败或尚未加载时不以 `0` 冒充真实数量。
- 各图层 API 按当前视图 extent 和缩放级别有界返回。未满足缩放门槛时提示用户放大，不偷偷返回全世界对象。

## 第三阶段：区域调查与高波动实体图层

### 区域反查玩家

- 用户可在地图选择矩形或圆形区域，设置 UTC 时间范围后查询曾被保留位置观察命中的玩家。
- 查询使用现有历史快照的 `position_x`、`position_z` 和 `observed_utc`，在 SQLite 中按包围盒、时间和结果上限过滤；
  圆形查询在数据库候选集上继续应用半径条件，不先读取全量历史。
- 返回每名玩家的 `crossplatformId`、显示名、首次命中、最后命中、命中观察数和最后命中坐标。命中表示“至少有
  一条被保留的观察位于区域内”，不证明持续停留、进入路径或未采样期间的位置。
- URL 保存区域类型、几何和时间范围；结果列表与地图高亮联动，可跳转历史玩家详情或载入该玩家轨迹。

### 高波动实体

- 动物和敌对实体作为独立图层，必须有缩放门槛、视图 extent、返回上限和刷新下限。
- 数据由游戏线程上的有界复制形成短生命周期不可变投影；HTTP 和前端不得触发世界全量扫描。
- 图层暂停、过期和失败必须可见；不保存为长期历史，不承诺重启后恢复。

## 安全、性能与可访问性

- 第 1 至第 3 阶段只允许 `Owner` 读取。匿名返回 401，非 Owner 返回 403；历史查询参数错误为 400，未知玩家
  为 404，存储或投影失败返回脱敏错误。
- 认证瓦片禁止 QueryString Token。浏览器和服务端日志不得记录 Authorization、完整本地路径或文件内容。
- 查询必须同时受时间、extent/zoom、条数和并发边界约束；一个图层失败不得造成地图整体不可操作。
- OpenLayers canvas 不是唯一的信息通道。在线玩家、轨迹观察、图层对象和区域查询结果均提供同步文本列表、
  焦点可见状态和可通过键盘触发的选择。
- 页面统一说明轨迹语义，不向普通用户展示技术缺口、缺失原因或丢失数量。历史详情页既有数据质量信息不受本
  地图呈现决策影响。

## 非目标

- 不建立地理坐标、道路导航、路径推断、速度推断、在线会话或停留时长模型；
- 不在当前三阶段提供多玩家轨迹叠加、热力图或物品地点搜索；
- 不在当前三阶段提供玩家背包或载具具体储物内容；两者需要独立的数据权限、查询和审计设计。
- 不提供从玩家资料进入的“专属监控区域配置”回跳流程；当前仅提供通用区域调查，出现真实消费者后再立项。
- 不提供小地图、地图旋转或 `minDistance` 二次筛点；固定朝北、标准缩放和轨迹保留策略是当前边界。
- 不改变历史快照保留策略，不从降采样数据插值或补点；
- 不在 HTTP 请求中读取游戏对象、扫描世界或加载离线玩家文件；
- 不从地图执行删除、传送、渲染或其他改变游戏/文件状态的操作。

## 验收

1. Owner 可在有限游戏坐标地图上查看各自带观察时间的在线玩家和游戏时间，并回看一名历史玩家的保留轨迹与快照；轨迹显示起终点且首次加载自动定位。
2. 已知缺失边界两侧不会连接；用户只看到自然断开的轨迹和统一观察语义说明，不看到 `gap` 或缺失原因。
3. 在线、历史、瓦片和每个业务图层独立表达可用性；一个失败不会抹掉其他成功数据。
4. 认证瓦片只接受 Header Bearer，URL、日志和静态资源中不出现 Token 或服务器文件路径；瓦片显示署名，可在浏览器端重新加载，未显示时使用不冒充世界地形的固定本地背景图。
5. 第二阶段可按需显示 region、历史玩家最后位置、商人、领地、载具和无人机，并在隐藏后停止对应刷新；图层显示已验证对象数量和可用的玩家资料跳转。
6. 第三阶段可按矩形或圆和时间范围反查命中玩家；查询有界且不把命中观察解释为持续停留。
7. 动物和敌对实体仅在满足缩放、extent 和结果限制时加载，不触发 HTTP 请求期世界扫描。
8. 在 320 CSS 像素宽度和键盘操作下，用户可通过同步列表完成筛选、对象选择和轨迹观察定位。
