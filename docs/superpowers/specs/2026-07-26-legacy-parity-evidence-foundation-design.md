# 旧版本功能对齐第一波：运行指标与证据闭环设计规格

## 上游、状态与波次职责

本规格落实[产品需求](../../PRD.md) `CAP-01`、`CAP-05`、`CAP-07`、`NFR-02` 与 `NFR-03`，遵循[旧版本功能对齐目标蓝图](../../architecture/legacy-feature-parity-target-blueprint.md)的运行指标、游戏事件、统一审计和聊天未闭环条目。当前系统事实仍以[系统架构](../../architecture.md)为准，验证策略以[测试策略](../../test.md)为准；本文在实现和证据完成前不是当前实现证明。

这是六波次规格集的第一波。它只补齐后续作业、玩家档案、经济和自动化共同需要的可观察事实，不建立通用 Event Bus、通用审计写模型或没有生产消费者的基础设施。

## 用户结果

- 管理员在概览中看到旧版已提供且当前游戏版本能够可靠采集的运行指标，并能区分未知、不可用、过期和部分可用。
- `Owner` 可以分别搜索管理员操作、专用动作记录和游戏事件，而不会把异步缺口表示为真实事件。
- `Owner` 可以管理玩家禁言；聊天页面完成 `zh-CN`/`en` 一致体验。
- 玩家游戏内命令通过登记目录路由到类型化处理器；第一波只交付有真实消费者的帮助命令，后续波次按能力注册经济、商店、传送、投票、兑换和绑定命令。

## 当前基线与保留边界

当前已有综合概览、角色裁剪、认证 SSE、在线/历史玩家、控制台命令审计、玩家动作审计、服务器操作审计、完整聊天代码切片和专用 `gap` 语义。第一波复用这些合同，不重写身份、事件窗口、历史 Store 或控制台工作台。

以下事实保持不变：

- 控制台原始日志不复制到 SQLite，跨重启原始证据继续由 7DTD 日志承担。
- 玩家动作、控制台命令、聊天和服务器操作继续拥有各自权威记录和状态机。
- `gap` 只表达异步观察可能不连续，不是一条玩家行为、管理员动作或已确认丢失事件。
- 高风险动作在审计意图无法持久化时保持 fail-closed；游戏事件、聊天历史等旁路观察保持 fail-open。

## 范围

### 运行指标

在现有游戏概览分区中增加游戏日时、血月状态、FPS、在线/历史玩家数、动物、敌对实体、活动实体、Chunk、掉落物和游戏内存。每个字段必须记录来源、单位、可空性和采样时间；无法从当前 `v3.0.1-b4` 可靠取得的字段返回 `null` 并附带稳定 warning，不以 `0` 替代。

游戏活对象只在 `GameThreadDispatcher` 内复制为不可变标量。一次成功采样内的字段共享同一 `observedAtUtc`；一项字段失败不能把主机分区或其他游戏字段改写为成功或失败。概览继续由 REST snapshot 作为权威状态，SSE 只触发刷新。

### 游戏事件

首批事件固定为玩家加入、离开、击杀与死亡。事件记录包含服务端生成的唯一 ID、事件类型、发生 UTC、观察 UTC、可用的稳定跨平台身份、运行期 entity ID、相关目标身份和批准的标量详情。缺少稳定身份时仍可保存事件，但不得按名称、IP 或 entity ID 合并为同一玩家档案。

SevenDays 回调只复制标量并 `TryWrite` 到单消费者有界队列，不等待 SQLite、不逐事件 `Task.Run`。队满、Store 失败和关服排空超时写入独立 `game_event_gaps`；恢复后继续接受新事件，不回填虚构记录。

### 统一审计查询

统一查询是只读投影，不成为新的权威写模型。SQLite 使用受 Persistence Adapter 所有的 `UNION ALL` projection/view，把现有专用记录映射为稳定摘要：

- `sourceKind` 与 `sourceId`；
- 操作者、目标、动作、发生时间、状态和 correlation ID；
- 是否存在可跳转的专用详情；
- 不包含消息正文、密码、Token、API Key、服务器路径或原始异常。

查询按 `(occurredUtc, sourceKind, sourceId)` 倒序 keyset 分页，支持时间、操作者、目标、动作、来源和状态筛选。游戏事件在独立标签和端点查询，可在同一审计工作台关联展示，但不映射为管理员操作。各来源的 gap 作为查询元数据或独立结果返回，不伪装成审计条目。

### 禁言

禁言以稳定跨平台身份为业务键，支持永久或带 UTC 截止时间的记录、原因、创建者、解除者和状态。仅 `Owner` 可以创建、更新和解除；读取同样为 `Owner` 专用。执行时只阻止受配置约束的玩家聊天公开广播，不阻断其他玩家、系统消息或服务端管理发送。

禁言状态在原始聊天协调器决定广播前读取进程内不可变快照。设置写入 SQLite 成功后才替换快照；到期记录按当前时间视为无效，并由低频清理移除。创建、修改、解除和自动到期均保留专用操作记录，记录不保存被阻止的完整聊天正文。

### 登记式游戏命令与双语收口

命令前缀沿用聊天设置。命令目录是显式注册的产品命令集合，每项定义名称、别名、参数验证、可用条件和类型化处理器；未知命令继续按原版聊天语义处理，不能降级为任意控制台命令。

第一波只注册一个只读 `help` 消费者，用于列出当前实际注册且已启用的命令。后续波次只有在对应能力和处理器同一变更中交付时才能新增命令。命令消息不进入彩色重写，执行结果只私发调用玩家并带稳定结果码。

现有游戏聊天四页、组件、验证和错误映射全部迁移到 `app/i18n`，补齐 `zh-CN` 与 `en` 同键断言。技术身份、模板变量、颜色值、协议名和原始游戏正文保持原样。

## 权限与接口

- 概览继续允许 `Owner`、`Admin`、`Viewer`，敏感主机字段按现有角色裁剪。
- 统一审计、游戏事件、禁言和聊天四页仅 `Owner` 可用；服务端授权不依赖导航隐藏。
- HTTP 使用独立的 `/api/v1/audit`、`/api/v1/game-events` 和 `/api/v1/chat/mutes` 合同；不扩展万能搜索或动作 payload。
- 成功列表使用有界 keyset cursor；非法筛选返回稳定 Problem Details，查询失败不清除 Admin 最后成功页。
- OpenAPI operationId 唯一，生成客户端仍经 Feature parser；Bearer 只进入 Header。

## 生命周期、失败与恢复

- 游戏事件 writer 在事件订阅前启动，关闭时先停止生产者，再完成 writer 并在有界截止时间内排空。
- 指标采样超时只使游戏概览分区进入明确不可用或保留旧值的 Stale 状态，不影响 OWIN 健康。
- 禁言 Store 写失败不改变运行时快照；聊天基础流程继续使用旧状态。
- 统一投影查询失败返回不可用，不修改任何专用记录；projection/view migration 可重复执行。
- 任何来源的技术异常都映射为稳定错误码，API、日志和 UI 不回显 SQL、路径或原始异常。

## 非目标

- 不持久化控制台日志正文，不建立跨进程 SSE sequence。
- 不建立通用事件总线、通用 handler registry、任意脚本或任意聊天命令框架。
- 不在本波实现经济、商店、传送、投票、兑换码、Discord 绑定或自动化动作。
- 不改变现有 Header Bearer、角色或引导 Owner 合同。
- 不把统一审计投影用于更新、删除或覆盖专用记录。

## 精简验证

- 指标：字段来源、单位、空值、同次采样、主线程复制和部分失败测试。
- 游戏事件：回调非阻塞、身份边界、队满/Store/排空 gap、SQLite keyset 和关服顺序测试。
- 审计：各专用来源映射、筛选、稳定 cursor、敏感字段排除和 gap 分离测试。
- 禁言与命令：永久/临时/过期、并发更新、广播阻止、其他消息放行、`help` 消费者、未知命令原版放行和审计测试。
- Admin：Owner-only 路由、查询 Stale、聊天双语键和桌面/窄屏聚焦组件测试。
- 稳定后后端与 Admin 各运行一次聚合门禁；真实 7DTD 只验证指标、四类事件、禁言和 `help` 命令的窄路径。

## 完成条件

- `CAP-01` 的批准运行指标具有诚实可用状态和采样时间。
- 管理审计与游戏事件可以分别检索，统一页面不改变专用权威记录，也不把 gap 伪装成事件。
- 禁言、帮助命令和聊天双语闭环具备代码、自动化和适用真实游戏证据。
- 没有新增无生产消费者的通用抽象；Current 文档只在实现与验证后提升事实。
