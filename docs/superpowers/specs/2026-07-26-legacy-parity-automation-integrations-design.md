# 旧版本功能对齐第五波：事件自动化、Discord 与 GeoIP 设计规格

## 上游、状态与波次职责

本规格落实[产品需求](../../PRD.md) `CAP-04`、`CAP-05`、`CAP-11`、`NFR-01`、`NFR-02`、`NFR-03`、`NFR-04` 与 `NFR-05`，依赖第一波游戏事件、第二波持久调度、第三波玩家动作和第四波经济/奖励/传送能力。当前实现仍以[系统架构](../../architecture.md)为准。

这是六波次规格集的第五波。自动化只编排已经存在的类型化消费者；Discord 和 GeoIP 是可独立停用的 Adapter/策略模块。不得用自动化反向创建任意脚本、任意 HTTP 或任意控制台平台。

## 用户结果

- `Owner` 可以创建由玩家加入、离开、聊天或 Cron 触发的固定规则，保存前校验并 dry-run，运行后查看每次匹配、跳过、失败和动作结果。
- 欢迎、轮播和血月公告接入同一规则/调度证据，但保留简单配置入口。
- 服主可以连接 Discord Webhook 或 Bot，配置频道、聊天桥、玩家绑定和批准的 Slash/远程命令。
- 服主可以按国家与 IP 规则控制玩家加入，并明确选择 GeoIP 不可用时 fail-open 或 fail-closed。

## 自动化规则模型

每条规则包含服务端 ID、名称、启用状态、固定触发类型、作用范围、条件树、按顺序动作、冷却策略、并发策略、创建/更新时间和最近执行摘要。规则配置是结构化数据，不保存代码、模板表达式、SQL、URL 请求体或任意命令原文。

### 触发器

首批触发器固定为：

- 玩家加入；
- 玩家离开；
- 普通聊天消息；
- 五字段 Cron；
- 血月状态进入批准阶段。

每次触发形成不可变 trigger snapshot 和稳定 `triggerId`。游戏回调只复制标量并非阻塞投递，Cron 复用第二波 scheduler。事件 gap 与规则执行记录关联为输入可能不完整，但不能生成虚构触发。

### 条件

条件仅支持批准字段上的 `equals`、`notEquals`、集合包含、数值范围、时间窗口、玩家组/权限和规则冷却。条件树限制最大深度、节点数和字符串长度。缺失值按显式 `Unknown` 处理；默认不满足需要确定值的条件，不能伪装成空字符串或零。

### 动作

动作白名单固定消费已经实现的类型化能力：

- 全局/私聊/公告消息；
- 发放批准物品或奖励包；
- 经济调整；
- 踢出、禁言；
- 执行由产品登记的受限命令；
- Discord 消息。

每个动作保存类型化参数和目标解析规则，不保存控制台原文。动作对应能力停用、目标不再有效或权限/目录发生变化时返回可识别失败，不寻找替代目标。

## 执行、幂等与 dry-run

保存规则先完成静态验证：触发器、条件、动作、依赖、字段和权限。dry-run 使用用户提供或最近真实触发的只读 snapshot，只返回条件判断、目标解析和预计动作，不持久化业务副作用、不发送游戏/Discord 消息、不扣费或发放。

真实执行以 `(ruleId, triggerId)` 为幂等键。冷却范围固定支持规则全局或规则加玩家；并发策略支持 `SkipIfRunning` 与 `QueueOne`。动作按配置顺序执行，每个动作有独立结果；规则可以选择 `StopOnFailure` 或 `Continue`，但已完成动作不自动回滚。涉及经济与发放的组合必须调用第四波可恢复 grant，不在规则引擎中复制事务逻辑。

执行记录包含输入摘要、条件结果、每项动作状态、开始/完成时间、稳定错误码和 correlation ID。重启后恢复未完成执行时，只重投具有幂等消费者的动作；结果未知动作等待人工处理。

## Discord 集成

### 配置与 Secret

支持 Webhook 或 Bot 两种模式、可选代理、频道映射、出站类型、聊天桥开关和远程命令 allow-list。Token、Webhook Secret 和签名材料使用服务器本地受限配置或专用 Secret Store；读取 API 只返回是否已设置和安全标识，日志/审计/前端资产不含完整值。

配置写入仅 `Owner`，采用版本冲突和测试连接动作。停用后停止新连接和投递，不删除配置、绑定或历史结果。

### 出站与聊天桥

出站消息由持久 delivery record 驱动，包含目标频道、内容摘要、重试次数、下次重试和最终状态。外部失败不阻断游戏聊天、事件、管理动作或规则其他步骤。重试使用有界指数退避和最大次数；人工重试生成新尝试但复用业务幂等键。

游戏到 Discord 的聊天只发送配置允许的频道和纯文本；Discord 到游戏的消息验证 Bot 来源、频道、成员权限和目标服务器，再通过类型化聊天 sender。桥接消息带来源标记和去环 ID，不能在两侧无限回声。

### 绑定、Slash 与远程命令

玩家绑定由游戏内一次性短码发起，短码保存摘要、短期有效且只能使用一次；完成后把 Discord subject 映射到稳定跨平台玩家身份。解绑由 `Owner` 或绑定玩家在批准入口执行并留记录。

Slash/远程命令是固定目录，每项定义 Discord 权限、参数 schema 和类型化用例。未登记命令、错误服务器、无权限成员或 allow-list 外命令直接拒绝，绝不降级到网页控制台或 shell。

## GeoIP 与加入策略

GeoIP Adapter 通过本地数据库或批准外部服务把规范 IP 映射为国家/地区和查询状态。缓存键为规范 IP，保存结果来源、数据库/服务版本、查询时间和过期时间；未知、私网、无效和服务不可用分别表达。

策略支持国家 allow/deny、精确 IP/CIDR allow/deny、面板配置的管理员绕过和优先级。精确 deny 优先于 allow，管理员绕过只适用于可确认的原生游戏管理员身份。每项配置必须选择外部数据不可用时 `FailOpen` 或 `FailClosed`，默认采用 `FailOpen` 并产生高可见告警；改变该默认属于产品安全决策，需要单独批准。

加入回调不得等待远程网络。外部服务模式只使用已有新鲜缓存；缓存缺失按失败策略处理，并在后台查询供后续连接使用。本地数据库读取可以在受控时限内完成，但游戏回调仍不得执行长时间 I/O。

拒绝结果使用配置文案，不向玩家泄露内部规则、代理或服务错误。命中、绕过、未知和失败形成访问策略记录，可在 Admin 诊断页查询。

## 接口与 Admin

- `/api/v1/automations`：规则、校验、dry-run、启停和执行记录。
- `/api/v1/integrations/discord`：配置摘要、连接测试、delivery、绑定与命令目录。
- `/api/v1/access-policies/geoip`：配置、缓存/版本摘要、诊断和最近决策。

页面使用结构化表单构造条件和动作，不提供 JSON/脚本编辑器。规则详情显示依赖能力、下一次 Cron、冷却、最近触发和逐动作结果。Discord 页面不回显 Secret；GeoIP 页面必须持续显示当前失败策略和数据版本。

## 权限、失败与生命周期

- 配置、dry-run、重试和诊断只允许 `Owner`；外部入站使用独立签名/平台身份，不建立面板管理会话。
- 自动化 consumer、Discord connector/delivery worker 和 GeoIP refresh 各自拥有明确生命周期；停用或关服先停止生产，再有界排空。
- 外部错误永远不能撤回原始游戏事件；结果未知不自动重放非幂等动作。
- 所有日志和 Problem Details 使用稳定错误码并脱敏 Secret、IP 策略内部和外部响应正文。

## 非目标

- 不提供任意脚本、任意 HTTP webhook 动作、任意 SQL、任意 shell 或远程控制台代理。
- 不实现跨服务器 Discord 路由、玩家网页登录或 OAuth 管理后台。
- 不实现复杂反作弊、跨服黑名单或未经批准的自动封禁。
- 不因模块停用删除业务数据；统一功能模块页面属于第六波。

## 精简验证

- 规则 schema、条件 Unknown、dry-run 无副作用、冷却、并发、幂等和逐动作恢复测试。
- SQLite 规则/执行/delivery/绑定、重启恢复和迁移测试。
- Discord 签名/权限/allow-list、Secret 脱敏、去环、重试和故障注入测试。
- GeoIP 规范 IP、CIDR、优先级、管理员绕过、缓存、FailOpen/FailClosed 和不可用测试。
- HTTP/OpenAPI、Admin 结构化表单、双语、权限和窄屏聚焦测试。
- 真实环境只执行一次 Discord sandbox 往返和一次受控 GeoIP 加入策略；不得对生产玩家执行未经确认的拒绝测试。

## 完成条件

- 固定规则可以校验、dry-run、执行和恢复，且只消费已存在的类型化能力。
- Discord Secret、入站权限、出站失败和聊天桥去环满足安全与状态诚实要求。
- GeoIP 在可用、未知和外部失败时按明确策略工作并留下诊断。
- 不存在可绕过产品权限和审计的任意脚本、远程命令或网络动作入口。
