# 旧版本功能对齐第四波：经济、奖励、传送与社区投票设计规格

## 上游、状态与波次职责

本规格落实[产品需求](../../PRD.md) `CAP-09`、`CAP-10`、`CAP-05`、`NFR-02`、`NFR-03`、`NFR-04` 与 `NFR-05`，依赖第三波提供的稳定玩家身份、游戏资源选择和类型化物品动作，并复用第二波持久作业与 Domain 状态机边界。当前系统事实仍以[系统架构](../../architecture.md)为准。

这是六波次规格集的第四波。经济账本先作为权威写模型交付，再由商店、奖励、传送费用和社区投票消费；不得先创建没有交易消费者的通用货币框架。

## 用户结果

- 服主可以管理一个服务器本地经济，玩家可以通过游戏内登记命令查询余额、转账、购买、兑换和领取奖励。
- 所有余额和库存变化可追溯，重复请求、并发购买、服务重启或奖励重投不会重复扣款或发放。
- 玩家可以在服主批准的规则下使用家、城市、好友和返回点传送，并参与踢人或重启投票。
- 任何扣款、物品发放、传送或投票结算失败都保留权威状态，不静默丢币、不伪造到达或成功。

## 经济账户与双重记账

每个稳定 `crossplatformId` 对应一个服务器本地账户。首版只有一种可配置显示名称的整数货币，金额使用非负 `long` 最小单位，不使用浮点数。系统账户承担发行、回收、商店和奖励对手方，所有余额变化通过不可变双重分录表达。

每个事务包含唯一 `transactionId`、类型、幂等键、发生 UTC、操作者/触发来源、关联玩家、借贷分录、状态和关联业务记录。一个事务的借贷总额必须相等；余额由同一 SQLite 事务中的账户行和分录原子更新。玩家账户不得为负，系统发行/回收账户不受该限制；禁止直接修改余额列绕过账本。

账户支持启用、冻结、管理员调整、玩家转账、交易查询和排行榜。冻结阻止玩家发起的支出与转账，但不阻止管理员补偿或显式退款。调整使用系统发行/回收账户并要求原因，不伪造为玩家交易。

## 商品、奖励包与发放状态

### 奖励包

奖励包由批准物品、货币和登记式受限动作组成。持久配置保存物品 `internalName`、kind、数量、品质约束和配置时目录版本；执行前必须用当前目录重新解析，不能持久依赖重启后不稳定的 `resourceId`。

一次发放创建唯一 grant operation。货币、库存和资格在 SQLite 事务中预留，游戏物品通过第三波类型化动作执行。全部成功后完成；游戏结果未知时进入 `PendingReconciliation`，不能自动再次发放。管理员可以查询、确认、退款或执行显式补偿，每个补偿都有新记录和幂等键。

### 每日奖励

每日奖励不继承旧版的货币连签或静态默认值。无参数玩家 `daily` 固定选择规则标识 `daily`，但该标识只定位 `Owner` 可维护的持久 `ruleId → rewardPackageId` 绑定，绝不内嵌奖励包或测试默认值。运行时只读取当前有效规则；不存在、停用或指向不可用奖励包的规则不能领取。领取以规则、稳定 `crossplatformId` 与 UTC `yyyyMMdd` 构成资格键，同一资格在重启、重复命令或结果未知后不得再次派发。规则修改只影响尚未开始的资格，不改写既有领取或 grant 的权威状态。

### 商店与库存

商品包含名称、描述、启停、价格、可选有限库存、每玩家限制、奖励包和排序。购买在一个事务中验证账户、冻结、商品状态、库存和限制，原子预留扣款与库存，再执行 grant operation。失败在副作用前释放预留；部分副作用或结果未知进入可恢复状态，不把商品标记为完整交付。

库存为 `null` 时表示无限；整数库存不得为负。并发购买通过条件更新保证只有一个权威结果。

### 兑换码、成就与在线奖励

兑换码保存摘要而不是可枚举明文，支持有效期、全局次数、单玩家次数、启停和奖励包。规范化后代码与玩家身份建立唯一兑换键，并发重复只能产生一条成功或拒绝记录。

成就由固定产品规则、进度和奖励包组成；在线奖励由可确认的累计在线观察或会话证据驱动。每个资格生成稳定键，事件重投、关服恢复和手动补发不能重复完成。证据存在 gap 时规则按配置暂停或标记不完整，不把未知时长算作已满足。

## 家、城市、好友与返回点

- 家：玩家拥有受配置数量限制的命名坐标，只能在批准条件下设置、列出、删除和传送。
- 私人家命令保留 `homes/sethome/delhome/home` 默认值，省略名称时使用 `home`；Owner 可配置四个命令名称、设置费用和私发提示，命令名称在下一次服务端启动注册。列表返回名称、世界和坐标。
- 城市：`Owner` 管理公开命名目的地，玩家只能选择已启用城市。
- 好友：邀请、接受、拒绝和移除使用稳定玩家身份；好友传送仍要求目标在线并明确允许。
- 返回点：只在一次已确认传送前保存当前点，不能由任意死亡、断线或未知动作覆盖。

传送规则包含独立启停、世界、边界、冷却、血月限制、费用、玩家状态和目标有效性。请求在 Application 预检后持久化动作意图并按需预留费用；SevenDays Adapter 在主线程重新确认身份、在线状态、世界、目标和限制，再执行类型化传送。

传送成功后完成扣款并更新冷却/返回点。副作用前失败释放费用；结果未知时保留预留并等待核对，不能宣称到达或自动重试。管理员直接传送同样使用固定目标和坐标，不接收控制台命令。

## 社区投票

首批投票类型为踢出玩家和计划重启。配置包含启停、发起资格、参与资格、持续时间、通过阈值、最小参与数、冷却和互斥范围。投票固定目标和发起时身份；每个合格玩家每轮只有一个有效选择，可以在截止前按配置变更一次。

结算使用数据库条件更新保证只发生一次。通过只创建既有踢出或计划重启的类型化动作意图，仍需重新验证目标与执行条件；投票通过不等于动作成功。失败、过期、取消和动作结果分别保留。

## 游戏内命令与 Admin

在第一波命令目录上注册实际消费者：余额、转账、商店、购买、兑换、奖励、家、城市、好友、返回和投票。命令参数使用相同 Application validator，未知或未启用命令只私发稳定错误，不降级为控制台执行。

Admin 新增经济账户/交易、商品/库存、奖励包、兑换码、成就/在线奖励、每日奖励规则、传送设置/城市和投票配置页面。上述经济与运营配置页面均仅 `Owner` 可用；`Admin` 和 `Viewer` 不能通过页面或 API 读取账本、余额或运营配置。玩家不登录管理网页。

所有页面使用 keyset 查询、稳定状态和显式确认；金额按当前语言格式化但保持整数语义。创建/编辑奖励包通过游戏资源目录选择，保存时服务端再次解析为持久内部名。

## 权限、审计与敏感性

- 管理配置与补偿仅 `Owner`；玩家命令以游戏稳定身份授权，不复用 `Viewer`。
- 每次经济事务、grant、购买、兑换、奖励、传送和投票都有专用记录与 correlation ID。
- 统一审计只引用这些记录，不复制完整兑换码、聊天正文或敏感玩家数据。
- 管理 API 不接受 SQL、控制台命令、文件路径或通用动作 JSON。

## 非目标

- 不支持多币种、跨服账户、真实货币支付、拍卖行、玩家网页登录或自由脚本奖励。
- 不根据名称、IP 或 entity ID 合并经济账户。
- 不把游戏内掉落或命令日志当作权威交付结果。
- 不提供无规则的任意坐标传送或投票后直接执行控制台原文。

## 精简验证

- Domain：双重记账、冻结、条件库存、资格、投票唯一结算、冷却和传送费用状态机。
- SQLite：并发转账/购买/兑换、幂等、事务回滚、重启恢复和 keyset 查询。
- Application/SevenDays：资源重验、固定身份、物品 grant、传送结果、未知状态和补偿。
- HTTP/OpenAPI：角色、独立 DTO、输入边界、Problem Details 和生成客户端。
- Admin：金额/库存/规则表单、资源选择、非乐观状态、双语和窄屏聚焦测试。
- 真实 7DTD 只验证一次购买发放、一次传送和一次投票动作；故障注入覆盖结果未知后的人工核对。

## 完成条件

- 账本在并发、失败和重启下保持平衡，任何余额变化都有不可变分录。
- 商店、奖励包、每日规则、兑换码、成就和在线奖励不会重复扣款或发放，并能恢复中间状态。
- 家、城市、好友、返回点和投票遵守身份、费用、冷却、血月和单次结算规则。
- 游戏内命令只路由到实际启用的类型化能力，不开放任意控制台或脚本执行。
