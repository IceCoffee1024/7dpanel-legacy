# 地图管理操作设计规格

## 上游与范围

本规格是[玩家坐标地图设计规格](2026-07-26-player-coordinate-map-design.md)之外的独立状态变更边界，
支持[产品需求](../../PRD.md) `CAP-02`、`CAP-05` 与 `NFR-02`。它只定义地图上发起的危险操作和长作业，
不改变只读图层查询合同。代码和适用验证完成前，不得写成当前实现。

## 能力范围

- 删除一块领地石记录；
- 从当前在线玩家标记发起传送，并通过选点或明确坐标指定目标；
- 在服务端重建或刷新已有地图瓦片资源；
- 渲染已探索区域；
- 渲染完整地图。

这些能力共用 Owner-only、确认、审计和状态诚实原则，但不共用一个通用“地图动作”请求：领地删除、玩家传送
和地图渲染分别拥有类型化用例、校验和结果模型。

## 权限与确认

- 仅 `Owner` 可见并可调用。服务端必须独立授权，隐藏按钮不能代替授权。
- 领地删除确认固定显示规范所有者、坐标和领地标识；提交后不能因图层刷新而替换目标。
- 玩家传送只允许当前在线、身份仍匹配且游戏 ready 的目标。确认固定显示玩家、来源坐标、目标坐标和世界；
  Stale/Offline 数据不能发起操作。
- 服务端瓦片资源刷新或渲染确认显示世界、范围、预计工作类型和可能的服务器负载影响。完整地图渲染使用更强确认，且同一
  世界不允许重叠执行互斥渲染作业。

## 执行边界

```text
Owner confirms typed request
  -> Application validates actor + immutable target
  -> game mutation: bounded game-thread dispatcher
     OR map rendering: bounded background job
  -> durable operation/audit state
  -> queued / running / succeeded / failed / result-unknown
  -> UI polls or subscribes to authoritative status
```

- 领地删除和玩家传送必须经现有有界游戏线程调度边界执行，不能由 HTTP 线程直接操作 7DTD/Unity 对象。
- 地图读取、服务端瓦片资源刷新和渲染不得在游戏主线程执行；使用单独有界后台作业队列，并限制同一世界并发。只读地图上的“重新加载瓦片”仅刷新浏览器 tile source，不进入本作业边界。
- 浏览器只提交产品级 world、范围、zoom 或实体标识，不得提交命令原文、脚本、输出目录或服务器文件路径。
- HTTP 接受请求只表示排队成功，不表示游戏动作或渲染成功。连接中断后通过操作 ID 查询权威状态。
- 执行前再次验证在线身份、领地所有权/存在性、世界和地图资源版本；验证失败必须安全拒绝，不作用于替代目标。

## 审计与恢复

- 每次请求记录 actor、动作类型、规范目标、确认参数、请求时间、开始/完成时间和终态；错误内容脱敏。
- 领地删除和传送记录可判断的游戏结果。超时或进程中断且无法确认结果时使用 `result-unknown`，不得显示成功。
- 地图作业状态至少为 queued、running、succeeded、failed、cancelled 或 interrupted；重启后保留可查询记录，
  interrupted 作业不自动伪装为 failed 或重新执行。
- 刷新/渲染输出先写临时资源并校验，再原子发布新的地图资源版本；失败继续提供上一个已验证版本。

## 前端交互

- 危险操作入口与只读 popup 分离，进入明确的操作面板或确认对话框。
- 传送不采用直接拖拽即提交。用户先选玩家，再选地图点或输入坐标，查看确认摘要后提交。
- 长作业显示排队、运行进度（若后端可证实）、成功、失败、取消和结果未知；刷新页面后可通过操作 ID 恢复。
- 操作成功后只失效相关图层或地图资源版本，不清空整个地图状态；失败保留当前地图和用户筛选。

## 非目标

- 不提供任意控制台命令、文件浏览器、路径输入或脚本执行；
- 不批量删除领地，不批量传送玩家；
- 不把渲染作业复用为通用后台任务框架；
- 不在只读地图第 1 至第 3 阶段提前创建这些运行时组件。

## 验收

1. 非 Owner 无法发现或调用地图管理操作；直接请求仍返回 403。
2. 领地删除和传送在执行前后都校验固定目标，身份或目标变化时安全拒绝。
3. HTTP 排队成功不会显示为最终成功；断线、超时和重启后仍能查询权威终态或 `result-unknown`。
4. 地图渲染不占用游戏主线程，使用有界并发，并在失败时保留上一地图版本。
5. 所有动作有脱敏审计；浏览器不能提供命令、脚本或服务器路径。
