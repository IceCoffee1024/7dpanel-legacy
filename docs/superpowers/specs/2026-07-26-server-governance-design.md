# 服务器治理功能设计规格

> 本规格描述服务器配置、黑白名单、双层权限和模组管理的目标设计，不代表功能已经实现。产品合同以 [PRD](../../PRD.md) 为准，页面规则以 [界面设计](../../design.md) 为准，当前实现事实以 [系统架构](../../architecture.md) 为准；后端和 Admin 的未来边界分别由[后端目标蓝图](../../architecture/backend-target-blueprint.md)与 [Admin 目标蓝图](../../architecture/admin-frontend-target-blueprint.md)拥有。

## 目标与范围

为单台 7DTD 服务器提供四个可独立交付的管理纵向切片：

1. 服务器配置：查看经过分类的 `serverconfig.xml` 属性，并安全修改获准字段。
2. 黑白名单：查看和单项维护 7DTD 原生封禁与白名单。
3. 权限管理：分别维护面板 `Owner`/`Admin`/`Viewer` 用户，以及 7DTD 游戏管理员和命令权限等级。
4. 模组管理：查看已发现模组、当前进程加载状态和下次启动状态，并安全切换下次启动状态。

本规格落实 `CAP-02`、`CAP-05`、`CAP-06`、`NFR-02`、`NFR-04` 和 `NFR-05`。四个切片共享现有认证、授权、审计、Problem Details、OpenAPI、生成客户端和游戏主线程调度边界，但不建立通用 CRUD 引擎、资源注册表或动态表单协议。

## 当前阶段决定

- 项目仍处于初始化开发阶段，不假设存在需要迁移的真实用户或生产数据。
- `config.json` 引导 `Owner`、已知开发默认凭据和 `allowInsecureHttp=true` 在当前阶段继续保留；用户管理上线不触发 Owner 迁移或 HTTPS 门禁。
- 明文 HTTP 上的网站密码和 Bearer 凭据传输是当前阶段明确接受的风险，不扩展为静态资源、日志、URL、Cookie 或错误详情中的凭据泄漏许可。
- 面板用户管理必须保留至少一个启用的 `Owner`，但不负责替换当前引导方式。
- 用户提供的外部 `7dtd-serveradmin` 参考仓库只作为功能和字段提取证据，不复制其源代码，也不沿用其大 Controller、非原子编辑或模糊状态文案。

## 非目标

- 不支持多服务器、跨服黑名单或自动封禁策略。
- 不包含禁言管理；旧项目的禁言页仅作为未来名单治理参考。
- 不提供批量删除、导入、导出或名单同步。
- 不提供模组上传、下载、更新、删除、依赖解析、热加载或热卸载。
- 不允许通过浏览器提交文件路径、目录、任意 XML 节点或控制台命令来实现这些功能。
- 不改变网页控制台允许 `Owner` 和 `Admin` 执行当前进程全部已注册命令的产品合同。
- 不在本变更中移除引导 Owner、默认开发凭据或明文 HTTP 例外。

## 参考项目功能盘点

| 功能 | 参考项目行为 | 本项目采用方式 |
|---|---|---|
| 服务器配置 | 遍历配置 XML 的 `property`，返回名称和值；前端用翻译键分组并逐项编辑 | 重新实现属性读取；增加字段目录、类型、敏感性、可编辑性、约束和重启提示；未知字段只读回退 |
| 封禁 | 玩家 ID、显示名、截止时间和原因；增删改、搜索、排序、分页和批量删除 | 保留字段与单项维护；移除批量操作；编辑使用一个类型化应用动作，不向前端暴露“先删后加” |
| 白名单 | 玩家 ID、显示名；增删改、搜索、排序、分页和批量删除 | 保留字段与单项维护；移除批量操作；由服务端处理原生操作结果 |
| 禁言 | 玩家 ID、名称、截止时间、永久状态、原因和创建时间 | 不进入本规格范围 |
| 游戏管理员 | 玩家 ID、显示名和 `0..2000` 权限等级 | 保留原生字段和等级语义，与面板角色分区展示和授权 |
| 命令权限 | 命令、`0..2000` 权限等级和动态描述 | 从当前命令注册表读取描述与有效等级；只修改游戏权限，不修改网页授权 |
| 模组 | 扫描 `Mods` 子目录和 `ModInfo.xml`/`_ModInfo.xml`，展示元数据、加载状态并通过元数据文件改名切换 | 重新实现受限目录解析；把当前加载状态与下次启动状态分离；切换后明确要求重启 |

## 授权矩阵

| 能力 | `Owner` | `Admin` | `Viewer` |
|---|---:|---:|---:|
| 查看和修改服务器配置 | 允许 | 拒绝 | 拒绝 |
| 查看黑白名单 | 允许 | 允许 | 允许，只读 |
| 新增、调整和移除黑白名单 | 允许 | 允许 | 拒绝 |
| 管理面板用户和角色 | 允许 | 拒绝 | 拒绝 |
| 管理 7DTD 游戏管理员 | 允许 | 拒绝 | 拒绝 |
| 管理 7DTD 命令权限 | 允许 | 拒绝 | 拒绝 |
| 查看模组清单和状态 | 允许 | 允许 | 允许，只读 |
| 切换模组下次启动状态 | 允许 | 拒绝 | 拒绝 |

导航隐藏和控件禁用只改善体验。服务端必须在返回数据或执行动作前按当前持久用户状态重新授权；直接访问无权路由进入统一 `Forbidden` 状态。

## 信息架构与页面

认证后的主导航新增“服务器配置”“访问名单”和“模组管理”；“设置”中的用户管理扩展为“权限管理”页面。权限管理使用三个分区：面板用户、游戏管理员、命令权限。

### 服务器配置

- 页面按字段目录提供的稳定分组展示名称、说明、当前值和“重启后生效”标记。
- 枚举、布尔、整数、数值和文本分别使用对应控件；前端表单模型不直接复用传输 DTO。
- 敏感字段不返回当前值，只显示“已设置/未设置”；首期不通过通用配置页修改敏感字段。
- 未收录在字段目录中的 XML 属性进入“其他（只读）”分组，不因缺少翻译而消失。
- 每次只编辑一个字段。提交确认显示字段名称、旧值、新值和生效时机；秘密值不出现在确认内容。
- 刷新失败时保留上次成功结果和原读取时间，并进入 `Stale`；写入结果未知时禁止自动重试。

### 访问名单

- 页面包含“封禁”和“白名单”两个页签，使用 URL 保存当前页签与搜索条件。
- 封禁列表显示玩家 ID、显示名、截止时间和原因；永久封禁使用明确文本，不伪造日期。
- 白名单显示玩家 ID 和显示名。
- 新增、编辑和移除都是单目标操作；危险确认固定显示玩家 ID、显示名和后果。
- 页面不提供批量选择。目标已变化或不存在时刷新列表并说明结果，不把旧行静默当作成功。

### 权限管理

- “面板用户”显示用户名、角色、启用状态和最近更新时间；密码永不回读。
- 创建用户需要用户名、初始密码、固定角色和启用状态；编辑允许改用户名、角色、启用状态和单独重置密码。
- 系统拒绝删除、禁用或降权最后一个启用的 `Owner`；并发请求以服务端原子结果为准。
- “游戏管理员”显示玩家 ID、显示名和 `0..2000` 权限等级；明确说明数值越小权限越高。
- “命令权限”显示命令、当前有效权限等级和当前进程提供的描述。命令描述只读，命令标识在编辑时不可改变。
- 页面持续说明两套权限互不映射：面板角色控制 Web，游戏等级控制 7DTD 原生权限。

### 模组管理

- 列表展示目录安全标识、名称、显示名、作者、版本、网站、描述、当前进程是否加载和下次启动是否启用。
- 后端只识别 Mods 根目录的直接子目录及受支持的元数据标记，不跟随越界路径。
- 当前进程状态只来自 7DTD 当前加载结果；磁盘状态不能伪装为已经加载或卸载。
- 切换动作确认显示模组名称、目录安全标识和“重启后生效”。成功后只更新下次启动状态。
- 7DPanel 自身及为当前进程提供必需运行时的受保护模组不可切换，页面说明原因。
- 缺失或损坏元数据的目录不进入可操作列表；诊断只记录安全摘要，不向浏览器返回真实绝对路径或内部异常。

## 前端边界

每个纵向切片拥有独立 Feature：

```text
pages
  ServerConfigurationPage -> features/server-configuration
  AccessListsPage         -> features/access-lists
  PermissionsPage         -> features/permissions
  ModsPage                -> features/mods
```

- 页面只组合 Feature 公共入口。
- 查询使用生成的 Pinia Colada definitions；服务器数据不复制到新的全局 Pinia Store。
- 搜索、页签和排序进入 URL；表单、确认目标和提交锁归所属 Feature。
- API 响应先经严格 parser 映射为页面模型；未知枚举、无效时间和越界等级进入明确失败状态。
- 写入成功只失效所属查询键；失败保留可安全复用输入；身份失效清除危险确认且不自动重放。
- 页面遵守现有 `zh-CN`/`en`、320 CSS 像素、键盘、焦点和 WCAG 2.2 AA 规则。

## 后端边界

四个 Application 能力分别拥有用例、模型和最小输出端口：

```text
ServerConfiguration -> IServerConfigurationStore -> Local adapter
AccessLists         -> IPlayerAccessControl      -> SevenDays adapter -> GameThreadDispatcher
IdentityManagement  -> IIdentityAdministration  -> SQLite adapter
GamePermissions     -> IGamePermissionControl    -> SevenDays adapter -> GameThreadDispatcher
ModManagement       -> IModCatalog               -> Local/SevenDays adapters
```

- Controller 只负责 HTTP 绑定、当前操作者和状态码映射，不访问 XML、SQLite、目录或活动游戏对象。
- 配置与模组文件 I/O 在受限 Local adapter 中完成；游戏名单与权限访问在 `GameThreadDispatcher` 内完成。
- 一个端口只在对应首个运行时消费者出现时创建，不建立跨四域的通用资源接口。
- 所有写操作产生操作审计；审计记录键名和安全摘要，不记录密码、敏感配置值、绝对路径或 Bearer 凭据。

## 数据与写入语义

### 配置字段目录

字段目录由产品代码维护稳定元数据：键、分组、值类型、可编辑性、敏感性、是否重启生效、枚举值和数值约束。读取时以 XML 当前键集合为事实，目录只解释和限制字段，不替代配置文件。

写入流程：

1. 验证请求键存在于当前文件且目录允许编辑。
2. 按字段类型规范化和验证值。
3. 检查客户端提交的版本标识与当前文件一致；不一致返回冲突并要求刷新。
4. 在同目录写临时文件并替换目标，失败时保留原文件。
5. 返回新版本标识、保存时间和是否需要重启。

### 7DTD 名单与权限

读模型在游戏主线程复制为不可变值后返回。新增、更新和移除使用类型化动作，不让 Controller 拼接控制台命令。应用结果区分成功、不存在、冲突、游戏未就绪、主线程不可用、原生拒绝和结果未知。

### 面板用户

用户、密码摘要和角色由现有 SQLite 身份边界拥有。用户变更和“至少一个启用 Owner”检查在一个能力型原子 Store 方法中完成。角色或启用状态变化后，后续请求和实时连接按现有复验机制使用最新用户状态；受影响用户的 Access Token 需要撤销，API Key 继续按创建者当前状态授权。

### 模组状态

模组目录安全标识只允许单个直接子目录名。解析后再次验证完整路径仍位于 Mods 根目录内，并拒绝目录分隔符、根路径和越界结果。目标状态切换通过受控元数据标记完成，采用同目录原子移动；当前进程不会热加载或热卸载。

## 错误与并发

- 首次查询使用 `Loading`；空集合使用 `Empty`，不显示为错误。
- 查询刷新失败但有旧数据时使用 `Stale`；无数据时使用 `Failed`。
- 游戏未就绪时，名单与游戏权限不可写；本地配置和模组清单仍可按授权读取。
- 相同目标的并发写入由服务端串行或冲突拒绝；前端提交锁不是并发正确性的来源。
- 文件版本冲突、最后 Owner 冲突和目标状态变化返回稳定 Problem Details code。
- 可能已开始但无法确认结果的非幂等动作返回 `Unknown`；页面先刷新目标或查询审计，不自动重放。

## 审计

至少记录操作者 subject、角色、动作、目标安全标识、请求时间、完成时间、结果、稳定失败原因和 trace/audit 标识：

- 配置只记录字段键、是否重启生效和结果，不记录敏感值。
- 名单记录玩家 ID、动作类型、截止时间和原因摘要。
- 面板用户记录目标 subject、角色/状态变化，不记录密码。
- 游戏权限记录玩家 ID 或命令名及权限等级变化。
- 模组记录目录安全标识和下次启动状态，不记录绝对路径。

## 精简验证策略

本变更按受影响边界验证，不在实现阶段默认运行 Playwright、发布、真实 7DTD 或重复全量复审：

1. 配置字段目录、值校验、版本冲突和临时文件替换的定向测试。
2. 名单、游戏权限的 Application 结果映射与 SevenDays adapter 主线程测试。
3. 用户角色矩阵、最后一个启用 Owner 和 Token 撤销的 SQLite/认证测试。
4. 模组安全路径、元数据解析、受保护模组和下次启动状态的临时目录测试。
5. 四组 Controller 的认证、授权、输入和 Problem Details 聚焦测试。
6. Admin parser、权限路由、关键表单和状态映射的聚焦 Vitest。
7. 代码稳定后只运行一次后端聚合测试、Admin typecheck 和生产构建。

真实 7DTD、受控 OWIN 浏览器、Windows/Linux 发布证据作为发布门禁缺口记录，不作为本次文档或常规实现完成条件；如果实现触及游戏版本兼容、静态事件或发布布局，再按 `docs/test.md` 扩大验证。

## 批准决定

本规格已确认：

- 采用上述授权矩阵。
- 当前初始化阶段继续允许明文 HTTP、引导 Owner 和已知开发默认凭据。
- 不执行 Owner 迁移。
- 首期不包含禁言、批量名单操作和模组上传/删除/热加载。
- 使用上述四个精简实施计划，不增加额外架构复审。
