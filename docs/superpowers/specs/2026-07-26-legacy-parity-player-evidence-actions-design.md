# 旧版本功能对齐第三波：玩家资料、物品证据与类型化动作设计规格

## 上游、状态与波次职责

本规格落实[产品需求](../../PRD.md) `CAP-02`、`CAP-05`、`CAP-08`、`NFR-02`、`NFR-03`、`NFR-04` 与 `NFR-05`，复用已完成的在线/历史玩家、坐标地图和[游戏资源目录设计规格](2026-07-26-legacy-parity-game-resource-catalog-design.md)。当前事实仍以[系统架构](../../architecture.md)为准；本文定义目标纵向切片，不表示玩家背包、物品来源或写动作已经存在。

这是六波次规格集的第三波。它先建立玩家资料与背包证据，再在同一波交付消费这些读模型的物品发放、删除和玩家重置。经济、商店、奖励和传送在第四波消费本波合同。

## 用户结果

- `Owner` 可以按稳定跨平台身份查看一个玩家的 Profile、会话、活动、位置、背包、技能和每日摘要，并看见每项来源的观察时间与完整性。
- `Owner` 可以比较相邻背包快照，区分已证实来源、仅观察到的数量变化和证据缺口。
- `Owner` 可以对固定在线玩家发放或删除批准物品，并执行批准的玩家重置；身份或游戏状态变化时不会作用于替代目标。
- 管理员补偿有独立原因、关联证据、幂等键和最终结果，不通过控制台原文执行。

## 稳定身份与资料聚合

玩家资料的唯一业务键是 `crossplatformIdentity.combinedId`。在线观察缺少该键时仍可出现在在线列表，但不创建档案、背包历史或长期动作目标。名称、IP、entity ID、原生平台 ID 和 Discord ID 都不能用于猜测合并。

Profile 是 Application 只读聚合，不复制为新的权威用户表。它组合现有历史玩家摘要、会话/事件、位置、背包、技能和每日活动来源，并为每个分区返回 `Available`、`Partial`、`Unavailable`、`Forbidden` 与各自 `observedAtUtc`。一个分区失败不能清除其他成功分区。

会话由可确认的加入和离开事件形成；缺少任一边界时标记开放或不完整，不推断持续在线。每日摘要按服务器配置时区分桶，展示事件和观察的已知计数，不把 gap 区间解释为零活动。

## 背包与技能观察

### 采集边界

背包和技能只在获准的玩家保存/数据事件或显式主线程读取中复制为产品自有标量。背包条目固定包含槽位、内部物品名、数量、品质、耐久/使用度、批准的 mod 标识和当前游戏版本；不把 `ItemStack`、`ItemValue`、容器或 Unity 对象带出回调。

内部物品名必须能在当前游戏资源目录解析；目录暂不可用时仍保存原始内部名并标记 `catalogResolution=Unavailable`，不能丢弃玩家证据。持久配置和历史保存 `internalName`、kind 与观察时目录版本，不保存重启后不稳定的 `resourceId`；HTTP 展示时按当前目录产生图标资源 ID。

技能快照包含当前版本能够确认的等级、技能点和批准技能/属性键值。未知、版本不支持和未加载分别表达；不把缺失值写成零。

### 持久化、保留与 gap

采集回调通过独立有界单消费者 writer 尽力写入 SQLite，不等待游戏主线程。快照以稳定玩家身份、观察 UTC 和服务端 ID 唯一，使用确定性保留策略限制增长；第一条、最新一条、发生变化的快照和管理员动作前后快照优先保留。

队满、Store 失败和关服排空超时形成玩家范围的 `inventory_gaps` 或 `skill_gaps`。gap 记录时间范围、原因和估计未持久化数量，但不是一条背包变化，也不能证明具体物品丢失。

## 物品变化与来源证据

相邻快照比较生成派生 diff：新增、减少、移动、属性变化和无法比较。diff 只陈述两个观察间的数量/属性差异，不断言变化发生的具体时刻或原因。

只有以下来源可以标记为 `Confirmed`：

- 7DPanel 自己完成且已确认终态的发放、删除、奖励或补偿动作；
- 当前游戏版本提供并经验证带唯一关联标识的批准事件。

其他变化标记为 `ObservedChange`；即使旧代码通过日志文本或时间相邻猜测，也不得推断为拾取、制作、交易、丢弃或作弊。已知 gap 与比较区间相交时，diff 标记不完整。

## 类型化玩家动作

### 共同规则

发放物品、删除物品和玩家重置分别拥有类型化请求、用例、SevenDays gateway 和专用审计，不使用万能 action DTO。请求固定：

- 操作者与 `crossplatformId`；
- 提交时 entity ID、在线观察时间和世界标识；
- 物品动作的当前目录版本、`resourceId`、解析后的 `internalName`、数量、可选品质和服务端确认摘要；
- 客户端生成请求键和服务端幂等记录。

Application 在副作用前持久化 Pending 意图；SevenDays Adapter 在 `GameThreadDispatcher` 内重新按稳定身份和 entity ID 双重匹配目标，再重新验证物品、数量、背包条件和世界。任何替换、离线、目录变化或版本不兼容都在副作用前拒绝。

### 发放与删除

发放只允许当前目录中可用于玩家的物品；隐藏物品需要 `Owner` 显式选择并强确认。数量受堆叠与服务端总上限约束。背包空间不足时不得静默丢弃；只有游戏 API 能明确报告掉落到世界且产品规格允许时才能作为独立结果。

删除必须指定精确内部名、数量和删除范围，默认只从玩家背包删除，不影响装备或其他容器。实际数量不足时不部分删除，除非用户明确选择并在请求中固定 `UpToAvailable` 模式；结果返回真实删除数量。

### 玩家重置

重置拆为已批准的独立类型：技能重置、背包清空和完整玩家数据重置。完整重置使用更强确认，并在副作用前保存当前玩家/背包证据；无法取得前置快照时拒绝执行，不能通过强制参数或隐藏分支跳过。

已开始执行后出现连接中断时返回 `ResultUnknown`，不得自动重试。终态写入失败同样不能改写为动作失败；后台恢复任务负责查询或提示人工核对。

## 接口与 Admin

- `/api/v1/players/{crossplatformId}/profile`：分区化玩家资料。
- `/api/v1/players/{crossplatformId}/inventory-snapshots`、`/inventory-diffs`、`/skills`：有界 keyset 查询与 gap 元数据。
- `/api/v1/player-actions/grant-item`、`remove-item` 和各重置类型：独立 POST，返回操作/作业 ID 与真实状态。
- `/api/v1/player-actions/{operationId}`：恢复最终结果。

页面新增玩家档案总览、背包、技能、活动与证据标签。桌面使用紧凑表格和详情抽屉，窄屏使用单列条目；每个分区独立处理 Loading/Partial/Stale/Unavailable。危险操作从固定玩家和当前快照打开确认，对话框显示玩家、世界、物品、数量、影响和目录版本；刷新不能替换目标。

历史页面保持只读，不能从旧快照直接发起动作。动作只从 Fresh 在线目标或经服务端重新验证的专用入口发起。

## 权限、安全与审计

- 玩家 Profile、背包、技能、来源和所有写动作仅 `Owner` 可用；当前在线基础列表维持既有角色合同。
- HTTP 和审计不返回游戏对象、磁盘路径、Token 或浏览器提供的控制台命令。
- Pending 意图持久化失败时不进入游戏线程；终态至少包含操作者、固定目标、参数摘要、发生时间、结果和 correlation ID。
- 物品来源查询只显示证据等级和关联记录；不提供“确定作弊”等推断标签。

## 非目标

- 不实现玩家网页账号、跨服身份合并、任意 NBT/ItemValue 编辑或背包文件直接修改。
- 不从控制台日志、名称、IP 或时间邻近猜测物品来源。
- 不在本波实现经济、商店、奖励包、兑换码、传送、投票或自动化发放。
- 不创建通用 inventory repository、动作 registry 或补偿工作流；抽象必须由本波真实读写消费者证明。

## 精简验证

- 当前游戏字段映射、主线程标量复制、目录解析、空值/版本和不可变性测试。
- SQLite 快照、diff、保留、keyset、gap、并发与迁移测试。
- Pending/终态、幂等、固定身份、数量边界、背包不足、目录变化、取消和 `ResultUnknown` 测试。
- HTTP 权限、独立 DTO、Problem Details、OpenAPI 和生成客户端测试。
- Admin 分区状态、固定目标确认、历史只读、桌面/窄屏和双语聚焦测试。
- 只执行一次受控真实玩家采集，以及发放、删除和每类重置的最小真实动作；完整重置只使用可丢弃测试玩家和可恢复世界。

## 完成条件

- 稳定玩家档案能够诚实聚合会话、活动、位置、背包、技能和每日摘要。
- 背包差异、来源等级和 gap 不互相冒充；所有来源结论可追溯。
- 发放、删除和重置只作用于重新确认的固定目标，并具有可恢复的专用结果。
- 后续经济、奖励、商店和自动化可以复用类型化目录与动作合同，而无需访问游戏活对象或控制台原文。
